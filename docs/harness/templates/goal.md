## 验收项

每条必须**可判真假**，且**写明证据形态**。写不出判据或证据形态的就不是验收项。

| # | 验收项 | 判据 | 证据形态 |
|---|---|---|---|
| 1 | | 具体到「点哪里 → 出现什么 → 多久内」 | 截图 `01_xxx.jpg` |
| 2 | | | 命令输出 |
| 3 | | 无 console error / 无 500 | CI run URL |

> 反例：「体验更流畅」「代码更清晰」——无法判真假。
> 正例：「个股页输入 `AAPL` 回车后 2 秒内出现总市值与 ROE，且 console 无 error」。

证据形态按改动性质选：有界面变化用截图；纯后端 / 基建 / 流程改动用命令输出、
`git log --graph`、文件片段、GitHub Actions run URL。**不要为了凑格式截一张无关的图。**

> ⚠️ **逐条自检：这个判据依赖的量，会不会被本 Goal 自己的改动搅浑？**
> 两类要防：判据依赖「合并后 / 发布后」才存在的东西（时序污染）；判据是行数、
> 覆盖率这类聚合数字而本 Goal 还会从别的方向影响它（度量污染）。
> 识别方式与改写方向见 [`../goal_workflow.md`](../goal_workflow.md) §判据自检。
