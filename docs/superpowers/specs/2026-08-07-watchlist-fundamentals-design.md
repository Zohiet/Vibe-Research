# 自选股页加载财报与研报信息 · 设计

> 2026-08-07 · brainstorming 产物。下一步走 `/vr-goal` 开 Goal（本文件是它的输入，不是 Goal Spec 本身）。

## 要解决什么

自选股页现在只有行情七列（名称/代码/现价/涨跌%/PE/PB/换手%）。需要在同一屏加上：

1. 最新财报的**发布时间**与关键同比
2. 投研机构的**研报**（个股数据页已能查的那些）
3. 结合研报评级与财报的**综合判断**

第 3 条的落地方式是本设计的核心决定，见「决策 2」。

## 已收敛的决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 这一页要回答什么问题 | 「谁最近有新变化，值得点进去细看」——时间信号优先 | 与 VR-GOAL-022「默认不替用户决定今天该关注谁」同向 |
| 2 | 「综合判断」怎么落地 | **VR 不下判断**，只把评级与财报如实聚合成客观数据；判断交给用户自己的 AI（页面已有「让 AI 读自选」） | 需要权衡的判断写死成公式必然失真；这正是本项目「只配数据、不给结论 + 三条 AI 出口」的产品前提 |
| 3 | 排版 | 一屏摊开、不做展开折叠；**放宽容器**，只放宽自选股一页 | 见「决策 3 的前情」 |
| 4 | 评级呈现 | 照实给计数，并在表头挂一句永久说明 | A 股卖方几乎不出减持/卖出，分布主要反映覆盖热度 |
| 5 | 目标价 | **要**。按机构去重后给**区间 + 给价机构数 + 最新日期**，不给平均值、不给隐含空间% | 见「决策 5 的实测依据」 |
| 6 | 新增列可否排序 | 除目标价外全部可排（目标价是区间，无单一可比值） | 沿用 VR-GOAL-022「数字能排、文字不排」，例外只有一条且能一句话讲清 |
| 7 | 东财挂了怎么办 | **不建降级链**，把失败做成看得见的；巨潮那条备用路径写进本文档存档，不写代码 | 见「降级」 |

### 决策 3 的前情

`Layout.tsx:170` 的 `mx-auto max-w-6xl` 把**所有 12 个页面**锁在 1152px（减 padding 后 1104px），与显示器无关。负责人日常是 27 寸屏，右侧一千多像素闲置。所以「8 列就要横向滚动」不是列多，是容器吃掉了空间。

放宽范围只取**自选股一页**：全局放宽会让研究记录 / 每日复盘 / 多空辩论里的 markdown 长文行宽拉到 2000px（排版上的倒退），且那是一次覆盖 12 页、没有编译器兜底的视觉变更——等同再来一次 VR-GOAL-021 的规模。**「表格类页宽 / 正文类页窄」的全局分道是正确的长期形状，但应当是独立的完整档 Goal**，已记入待办。

### 决策 5 的实测依据

近 180 天，实测 8 只样本：

- **目标价覆盖率仅 18%**（100 篇研报中 18 篇带目标价），8 只里 4 只完全没有。这一列大面积空白是常态，不是 bug。
- **样本小到「平均」是伪精度**：中国平安 3 篇、绿的谐波 1 篇。
- **失效值的危害已实际出现**：绿的谐波唯一那篇目标价 238、现价 348，隐含 −32%，而报告是 4 个月前写的。**日期不显示，这一格就是在说谎。**
- **必须按机构去重**：宁德时代 9 篇带目标价实际只来自 **3 家**（东吴 4 篇 618→656、交银 4 篇均 512、群益 1 篇）。贵州茅台的群益证券把 1525 下修到 1430——按篇统计会把它自己已经作废的 1525 留在区间里。
- `indvAimPriceL` / `indvAimPriceT` 基本相同（35 篇中仅 1 篇自带区间），**区间只能跨机构聚合**。

不给隐含空间%的理由不是红线，是**那个数不属于任何机构**：它由 VR 拿目标价除以实时现价算出，且开着实时行情会每 3 秒变一次，会是全表唯一一个自己跳动的「机构观点」。

## 数据源（全部已实测）

| 数据 | 接口 | 成本 | 依赖 |
|---|---|---|---|
| 财报（含发布日、营收/净利同比、ROE、毛利率） | 东财 `datacenter-web` `reportName=RPT_LICO_FN_CPD`，`filter=(SECURITY_CODE in (…))(ISNEW="1")` | **多只一次请求，0.26s** | 无（走 `em_get`） |
| 研报（评级、机构、目标价、日期） | `reportapi.eastmoney.com/report/list`，按代码单查、加 `beginTime` 收窄到近 180 天 | 5 只串行 0.31s，20 只约 1.2s | 无 |

**「近半年」全文一律指 180 天**（`beginTime = today - 180d`），界面文案与代码常量取同一个值。

字段对应：`NOTICE_DATE`=发布日、`REPORTDATE`=报告期、`QDATE`=期次、`YSTZ`=营收同比、`SJLTZ`=净利同比、`WEIGHTAVG_ROE`、`XSMLL`=毛利率；研报侧 `emRatingName`、`orgSName`、`publishDate`、`indvAimPriceL/T`。

**这条路顺带绕开了 501**：现有 `/api/financials` 走 akshare（`stock_financial_abstract_ths`），逐只、慢、缺依赖直接 501，且**不提供发布日**。新源两样都解决。

实测评级取值分布（10 只 / 122 篇）：买入 95、增持 23、持有 2、中性 2、**减持 0、卖出 0**。「持有」与「中性」语义重叠，合并为一类。

## 架构

```
astock.py（数据层）
  batch_earnings(codes)      → 一次 em_get，{code: 最新一期业绩}
  _parse_earnings_row(row)   → ★纯函数
  eastmoney_reports(code, …) → 已存在，加 beginTime 参数
  summarize_reports(rows)    → ★纯函数：吃研报列表 → {篇数/覆盖机构/评级计数/目标价聚合/最新日期}

app.py
  GET /api/earnings?codes=…        缓存 6 小时
  GET /api/report-summary?codes=…  缓存 30 分钟

frontend
  lib/api.ts        两个方法 + 类型
  hooks/useWatchlistBrief(codes)   两请求并发、各自独立 loading/error
  pages/Watchlist.tsx              新增 12 列（7→19，加移除列共 20）+ 排序扩展 + AI context 扩充
  router.tsx / Layout.tsx          handle: { wide: true } → max-w-[1800px]
```

**两个纯函数是本设计最重要的可测试性决定。** `summarize_reports` 吃 `list[dict]` 吐 `dict`、不发任何请求，于是评级归类、目标价按机构去重、90 天陈旧判定、0 篇 / 1 篇 / 目标价全空这些边界全部能在离线单测里穷举断言。照抄 `portfolio.render_snapshot()` 被验证过的路子（CLAUDE.md：「所以内容正确性能直接断言文本」）。

**两个端点而不是一个**，是为了独立降级：研报源挂了，财报那五列照常显示。

端点约定沿用 `/api/quote`：`codes` 逗号分隔、返回 `{code: {...}}`。每端点上限 100 个 codes（超出 400），前端按 100 分批并发合并——避免自选 120 只时表格静默少一半。

**刷新时机**：只在 `codes` 变化时拉，**不接实时行情那条 3 秒轮询**。财报一天变不了一次，研报一天几次。

### 宽屏实现

不用负 margin 撑破父容器（脆弱，且与 `overflow-auto` 打架）。走 react-router 的 `handle`：

```tsx
// router.tsx
{ path: "/watchlist", element: <Watchlist />, handle: { wide: true } }

// Layout.tsx
const wide = useMatches().some((m) => (m.handle as { wide?: boolean })?.wide);
<div className={cn("mx-auto px-6 py-6", wide ? "max-w-[1800px]" : "max-w-6xl")}>
```

声明式、与路由同处一地，将来放宽持仓页是改一行。按字号量算 20 列约需 1600px，1800px 有富余；窄屏由 `overflow-x-auto` 兜底。

```
名称    代码   现价  涨跌%  PE   PB  换手% 期次  发布日 营收同比 净利同比 ROE  篇 覆盖 买入 增持 中性  目标价（给价机构·日期）  最新
宁德时代 300750 388.1 -0.8 35.0 6.1 1.1 26半年 07-25 +54.8% +42.0% 10.6% 25  11   20  5   —   500–656 · 3家 · 07-28   07-31
贵州茅台 600519 1309  +1.2 22.1 8.3 0.4 26一季 04-25  +6.3%  +1.5% 10.6% 32  15   26  4   2  1430–1865 · 4家 · 07-20  07-23
绿的谐波 688017 347.8 -1.1 88.0 9.4 3.2 26一季 04-23 +42.9% +61.2%   —     5   5    4  1   —      238 · 1家 · 04-23      05-26
五粮液   000858 128.3 +0.3 15.2 3.1 0.6 26一季 04-30 +33.7% +82.6%   —     4   4    3  1   —          —              05-06
```

约定：

- **两个「家数」必须分开命名**：「覆盖」= 近半年发过研报的机构数；「给价 N 家」= 其中给了目标价的机构数。同一行 11 与 3 含义不同，不共用「家」字。
- **只有 1 家时不画区间**，直接给单值（绿的谐波 `238 · 1家 · 04-23`），别把一家之言排版成共识。
- **目标价格里的日期** = 给价研报中最新那篇，与最右「最新研报日」不是一个数（宁德 07-28 vs 07-31）。因此保留独立的「最新研报日」列——否则没有目标价的股票（五粮液）连一个研报日期都看不到。
- **陈旧标记**：目标价日期超 90 天用 `text-subtle` 弱色（VR-GOAL-021 的三级文字体系，**不用透明度**）。
- **0 篇 ≠ 取不到**：近半年确实 0 篇研报显示 `0`；取不到才显示 `—`。这是 VR-GOAL-014「不返回假的 0」的镜像——反过来也不许把 0 说成缺失。
- **评级说明常驻**：表头「近半年研报」旁挂提示——*A 股卖方极少出具减持/卖出评级，评级分布主要反映覆盖热度，不代表机构看好程度对比。*
- **可排序**：现价、涨跌%、PE、PB、换手%、发布日、营收同比、净利同比、ROE、篇数、覆盖机构、买入、增持、中性、最新研报日。**目标价不可排**（区间无单一可比值）。取不到值的行**恒沉底**，不用 `?? 0` 兜底——沿用 VR-GOAL-022 已立的规矩，但注意排序值现在来自 quotes 与 brief **两个数据源**，`orderedCodes` 的 `useMemo` 依赖要同时包含两者。
- **AI context 扩充**：把财报与研报聚合拼进 `aiContext`，让「综合判断」真正由用户自己的 AI 给出（决策 2 的兑现点）。

## 降级

「东财不通」是三件不同的事：

| 形态 | 应对 | 状态 |
|---|---|---|
| 用户开着科学上网代理连不上 push2 | `em_get` 内建直连优先 / 失败降级系统代理 | **已解决**，新端点白嫖 |
| 临时 502 / 限流 | 缓存 + 失败不写缓存；旧数据继续显示并标时间 | 照抄现有模式 |
| 接口下线 / 字段改名 | 需换源，见下 | 不实现 |

天然冗余：`reportapi.eastmoney.com` 与 `datacenter-web.eastmoney.com` 是两台不同主机，且研报那条不走 `em_get`（自己的 session），两条同时挂的概率不高。

失败的表现形式：卡片顶部一条提示条说明哪一块不可用，表格其余列照常——照 `wikipush` 的「失败不抛，降级成不可投 + 原因」。**副功能不许干掉自选股页。**

### 备用路径（存档，不实现）

| 数据 | 备选 | 成色 |
|---|---|---|
| 财报发布日 | **巨潮 cninfo** `hisAnnouncement/query` | 已交叉验证一致；需 orgId |
| 营收/净利/ROE | 同花顺（akshare，已有 `astock.financials`） | 能用，但慢、需 akshare、无发布日 |
| 研报评级/目标价 | **无等价免费源** | 没有 |

巨潮实现要点（均已实测）：orgId 映射来自 `http://www.cninfo.com.cn/new/data/szse_stock.json`（6230 只，0.24s，可缓存一天）；`category` 传 `category_ndbg_szsh;category_bndbg_szsh;category_yjdbg_szsh;category_sjdbg_szsh`；`stock` 传 `f"{code},{orgId}"`——**orgId 留空会返回全市场 48 万条**。

交叉验证：茅台 2026-04-25、宁德 2026-07-25，与东财 `NOTICE_DATE` 完全一致。

**但它做主源会错**：五粮液最新一条是「2025年度报告（**英文版**）」、绿的谐波是「2025年年度报告(**更正后**)」，都不是最新报告期，须靠标题过滤「英文版 / 更正 / 摘要」。做兜底可以，做主源会引入一类很难查的错。

**为什么现在不写**：研报侧压根没有备选，链只能建一半；且 CLAUDE.md 明写「从不执行的代码就是 bug 藏身处」。VR-GOAL-018 那条三级降级链是**有实际触发场景**才做的，这里没有。真哪天东财下线，照本节实现是半天的活，且那时能看见真实故障形态。

## 合规口径的变更

**目标价是价格预测。** CLAUDE.md 现在白纸黑字写着「不预测涨跌」，产品放了目标价而文档还写禁止，就是本项目最忌讳的「文档与真相漂移」。

因此本次**必须同步改 CLAUDE.md**，把口径写清楚：

> 机构目标价按原样转述，必须标注给价机构数与日期，超 90 天弱化显示；**VR 不自行推算目标价、不计算隐含涨跌空间**。

这是负责人在本轮明确拍板的口径变更，不是实现时的自作主张。
