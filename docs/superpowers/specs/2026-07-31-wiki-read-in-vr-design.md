# 在 VR 里看到该股票的 wiki 研究页（子课题 C）

- **日期**：2026-07-31
- **状态**：设计已确认，待转 Goal
- **前置**：VR-GOAL-009（沉淀 → wiki）、VR-GOAL-011（持仓快照 → wiki）已打通两条**写**通路；
  这是第一条**读**通路，也是 VR↔wiki 三个子课题的最后一个

## 要解决什么

VR 看行情、wiki 存判断。你在 VR 里盯着一只股票时，**当初为什么买它、什么条件下该减**
这些东西全在 wiki 里，而 VR 完全不知道它们存在。

本设计让 VR 能**读**（且只能读）wiki 里按股票代码组织的研究页：
人看摘要，AI 讨论时可选带上全文。

## 实测到的事实（决定了设计形状）

| 事实 | 影响 |
|---|---|
| wiki 有 **39 个**按六位代码命名的页（公司 37 + 基金 2）| 匹配面足够大，值得做 |
| frontmatter 的 `ticker` 覆盖 **39/39**；`market` 39/39、`updated` 39/39、`sources` 39/39、`sector` 37/39、`industry_chain` 36/39 | **靠 `ticker` 匹配**，不解析文件名的全角括号 |
| 「一句话定位」覆盖 **35/39（90%）** | 可用，但必须容忍缺失 |
| 页面体积：中位 **8.5k 字符**、平均 10.8k、**最大 24k**（寒武纪）| 全文进 context 必须是**可选**的，不能默认 |
| VR 的问 AI **每轮重发 `context`** | 同上，默认带会让每个来回都多驮 ~10k 字符 |
| `StockData` **没有 URL 参数**（`code` 是组件内 state）| 持仓页记号做成提示、不做跳转，避免连带改路由 |

## 已确认的决策

| # | 议题 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 显示到什么程度 | **人看摘要，AI 讨论时用全文** | 摘要回答"我研究过这家、当初怎么说的"；全文只在真要讨论判断时才需要。渲染全文会把 VR 变成劣化版 Obsidian |
| 2 | 全文何时进 context | **面板上一个勾选，默认关** | 价值场景很集中（"我当初的判断还成立吗"），是你主动发起的低频对话。为低频场景加显式开关，比让所有对话都变重划算。**勾这个动作本身就是给 AI 的信号** |
| 3 | 接哪些页面 | **个股数据页 + 持仓页** | 自选可能几十只、观察池 37 页大面积命中 —— 记号密到等于没标记。**标记只在稀疏时才有信息量** |
| 4 | 摘要显示什么 | **frontmatter 关键字段 + 一句话定位 + 节标题清单** | 三样都**不需要理解语义**：键值对、固定位置的一行、`^## ` 行。VR 全程当字符串处理，wiki 改内容不会让 VR 出错。**不取"最近一节估值快照"**——那要 VR 从节标题解析日期，等于教它认 wiki 的书写约定 |
| 5 | 后端模块边界 | **新开 `wikiread.py`，全模块无写操作** | 这个功能唯一的真实风险是「VR 写坏你的研究页」。`raw/vr/` 丢了可以重投，公司页写坏了没有第二份。**用模块边界把读写物理隔开，比十条注释管用** |
| 6 | 持仓页记号的行为 | **只做悬停提示，不跳转** | `StockData` 无 URL 参数，跳转要连带改路由 + state 初始化。而持仓页你想知道的往往就是"我当初怎么说的"那一句——**当场给了就够** |

## 架构

```
backend/wikidir.py     新增 ~25 行：WIKI_DIR + require_wiki() + status()
                       「这个目录是不是 llm-wiki」的校验规则只有一处
backend/wikipush.py    改 3 行：私有的 WIKI_DIR / _require_wiki 换成 import wikidir
backend/wikiread.py    新增：**全模块没有任何写操作**
```

### ⚠️ 抽取时的静默失效陷阱

`wikipush.py` **必须写成 `import wikidir` + 函数内引用 `wikidir.WIKI_DIR`**，
不能写 `from wikidir import WIKI_DIR`。

原因：现有测试有 **11 处 `monkeypatch.setattr(wikipush, "WIKI_DIR", ...)`**
（`test_wikipush.py` + `test_portfolio_snapshot.py`）。若用 `from ... import`，
patch `wikipush.WIKI_DIR` 会改到那个名字、但 `require_wiki()` 读的是 `wikidir.WIKI_DIR`
——**测试会绿着通过、实际什么都没验**。

用 `import wikidir` 则这 11 处必须显式改成 patch `wikidir`，**失效变成可见的，而不是静默的**。
这是本次改动最容易出错的一步。

## 端点

| 端点 | 给谁用 | 返回 |
|---|---|---|
| `GET /api/wiki/stocks` | 持仓页记号 | `{enabled, error, codes: ["002436", …]}` 一次拿全 |
| `GET /api/wiki/stock/{code}` | 个股页摘要 | `{title, market, sector, updated, sources, oneliner, sections: []}`；无该页 → `null` |
| `GET /api/wiki/stock/{code}/full` | 勾选后取全文 | `{text}` 原始 markdown |

**缓存**：扫 39 页的 frontmatter 建 `ticker → 路径 + 摘要` 映射，**TTL 60 秒**
（照 `market.py:17` 的现成模式）。wiki 页不是高频变动的东西，60 秒陈旧无害。
**全文不缓存**，按需读——它大且用得少。（TTL 只作用于 `ticker → 摘要` 这层映射。）

## 界面

### 个股数据页 —— 摘要卡片

位置在**基本信息 / 估值卡之后**，不在页面底部。这是**你自己的判断**，与下面的外部数据不是一类；
沉到最底会被当成附录。但也不放在行情之上——打开这页首先是要看行情。

```
📓 你的 wiki 研究页 · 更新于 2026-07-08 · 3 份来源
PCB + IC封装基板（FCBGA/ABF） · A股·深交所主板
「国内唯一量产 ABF 载板，客户验证壁垒；但估值极贵（PE 142-408x）」
写过：业务描述 / 护城河分析 / 核心财务特征 / 成长驱动 / 主要风险 / 估值框架 / 同类对比 / 估值快照 ×3
```

**wiki 里没有这只股票时什么都不显示**——不出现「暂无 wiki 页」，那是纯噪音。

### 持仓页 —— 记号

持仓行加 📓，悬停显示「更新于 YYYY-MM-DD · 一句话定位…」。不跳转。

### 问 AI —— 通用的额外上下文

`AskAiButton` 是 5 个页面共用的通用组件，**不能塞 wiki 专属的勾选框**。改成通用形状：

```ts
extraContext?: { label: string; fetch: () => Promise<string> }
```

个股页传 `{ label: "带上 wiki 研究页", fetch: () => api.wikiFull(code) }`。
组件**不知道 wiki 是什么**，只知道"有个可选的额外上下文，勾了就去取"。
将来别的页面要带别的东西（比如持仓页带交易流水），走同一个口子。

**取的时机**：勾选后**发第一条消息时才拉全文**，不是勾上就拉——你可能勾了又取消。

**勾选项必须标出体积**：`带上 wiki 研究页（约 12k 字）`。这个数字从摘要接口一并返回
（扫 frontmatter 时顺手记下文件字符数，零额外成本）。
理由：**代价由你承担、每轮重发，就得让代价可见**——最大的一页 24k 字符，
不标出来你不会知道自己勾了什么。

## 错误处理

沿用 VR-GOAL-009 已定的口径，**不新造**：

| 情况 | 表现 |
|---|---|
| `VR_WIKI_DIR` 未配置 | **静默**，整块不渲染 |
| 配了但目录读不到 | 页面顶部提示条说明原因（**"没配"和"配了但坏了"必须分得开**）|
| 该股票没有 wiki 页 | 什么都不显示 |
| 某页 frontmatter 坏了 | **跳过那一页，其余照常**（照 `myaccumulation._parse` 的 best-effort）|
| 美股 / 港股 | `ticker` 全是六位数字，字母代码天然查不到 → 不显示。**不需要特判** |

## 测试

| 类型 | 覆盖 |
|---|---|
| pytest | 摘要字段正确（含 `sector` / `industry_chain` 缺失时省略）；**一句话定位缺失不报错**（实测 4/39 没有）；坏 frontmatter 只影响该页；未配置 → `enabled=false`；目录读不到 → 降级带原因；全文与原文**哈希一致**；缓存 TTL 到期后重扫 |
| pytest（红线）| **只读指纹断言**：跑完所有读端点后，假 wiki 目录的 `(路径, 大小, mtime_ns)` 集合**与跑前完全一致**。将来有人往 `wikiread.py` 加一行写操作，这条当场变红 |
| E2E | 个股页输入有 wiki 页的代码 → 摘要卡片出现；持仓页记号出现 |

**E2E 的前提改动**：沙箱的 `fake-wiki` 现在是空壳（只有 `CLAUDE.md` + `wiki/`）。
要测摘要，得让 `ci.ps1` / `dev.ps1 -Sandbox` 生成时**顺带造一两个假公司页**。
这是第三次动 `ci.ps1`——改动很小（两个 heredoc），如实标出。

## 不在范围内

- 不把 wiki 全文渲染进 VR 界面
- 不解析节内容、不判断"哪节比较新"
- **不做任何反向写入**（VR 绝不写 `wiki/` 下的任何文件）
- 不给 `StockData` 加 URL 参数
- 不做非股票类 wiki 页（概念 / 行业 / 判断记录）的接入

## 已知风险

- **抽 `wikidir.py` 要动 11 处测试的 patch 目标**，且写法错了会静默失效（见上）。
  这是本次最容易出错的一步，实施时先跑 `test_wikipush.py` 确认它**真的会因为 patch 错目标而变红**。
- **摘要依赖三个弱约定**：frontmatter 键值对、`一句话定位` 在 H1 之后、节标题用 `^## `。
  前两个有实测覆盖率兜底（39/39、35/39），第三个是 markdown 通用语法。
  wiki 若大改书写习惯，摘要会退化成"少显示几行"，**不会报错**——这是有意的降级方向。
- **全文进 context 的成本由用户承担**：最大 24k 字符 × 每轮重发。勾选是显式的，
  但**界面上应当标出体积**（比如「带上 wiki 研究页（约 12k 字）」），让代价可见。

## 合规

- 只读用户自己写的研究内容，不产生任何观点 / 评分 / 买卖指向
- 本机文件读取，不经网络
- `VR_WIKI_DIR` 未设即整体关闭，不影响开源用户
