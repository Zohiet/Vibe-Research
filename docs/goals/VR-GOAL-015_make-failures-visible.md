今天的三场排查，卡点是同一个——**东西坏了或旧了，但没人说**。

| 症状 | 真相 | 为什么没早发现 |
|---|---|---|

## 实测到的事实

**① 辩论：单个角色失败会污染最终产物，且不留痕**

`debate.py` 的失败处理是对的一半、错的一半：

```python
except Exception as e:
    yield {"type": "error", ...}
    yield {"type": "stage_done", ..., "failed": True}
    continue          # 失败内容不进 transcript —— 这一半是对的
```

不把错误信息当论据喂给下游，对。**但后果是主持人拿到「多方陈述 + 空方陈述 + 多方反驳」，
唯独少了空方反驳——它在总结一场「多方反驳了、空方没反驳」的辩论，而它并不知道少了一块。**

一次外部抖动，污染的是最终产物，**且看不出被污染**。

**② 这次失败是外部的、间歇的，不是代码 bug**

A/B 实测（每组 3 次，共 6 次；另加一场完整的二轮辩论 5 次调用）：

```
带 MCP    #1 rc=0 24s   #2 rc=0 18s   #3 rc=0 20s
屏蔽 MCP  #1 rc=0 18s   #2 rc=0 21s   #3 rc=0 22s
```

**11 次调用 0 次失败** —— 复现不出来。「是不是排查中挂上的 MCP 导致的」这个怀疑**被证伪**。
按 systematic-debugging 的规定，查到这一步该改为「实现适当的处理（重试）」而非继续追因。

**③ 日志：今天三次排查全卡在这**

- `ci.ps1` 起沙箱时重定向到 `.sandbox-data/ci-backend.log`（**有日志**）
- `dev.ps1` 起的日常实例只打在窗口里（**没有日志**）

**最需要日志的恰恰是日常实例**（真实数据、真实使用），结果只有它没有。
第三次排查时，我为了拿一个 traceback **不得不绕开启动脚本、自己另起一个带重定向的进程**。

窗口输出还有两个隐性损耗：**scrollback 有上限**、**关窗口就全没了**。

**④ 资讯雷达：不刷新就永远是旧的，且缓存放错地方**

```python
CACHE_DIR = os.path.join(HERE, ".cache")   # HERE = backend/ —— 在仓库里
def get_radar(force=False):
    if force: return fetch_radar()
    return load_cache() or skeleton()      # 从不自动刷新
```

实测 `backend/.cache/radar.json` 时间戳 **7-31 11:13**（当天是 8-1）。两个后果：

- **不点「刷新」就永远显示上次抓取的结果**，页面上也不说它是哪天的
- **缓存不遵守 `VR_DATA_DIR` 隔离** —— 沙箱与真实实例**共用同一份**。
  E2E 跑一次刷新就会改掉用户日常看的数据，违反 `CLAUDE.md` 的「用户数据都在 `~/.vibe-research/`」红线

## 待 grilling 拍板

| # | 议题 | 为什么要拍板 |
|---|---|---|
| 1 | **三件事该不该放在一个 Goal 里** | 主题同源（失败/陈旧不可见），但落在三块互不相干的代码上。捆在一起 = 想单独撤某一件时撤不掉 |
| 2 | 日志落哪儿、留多久、窗口还要不要输出 | 日志含股票代码/wiki 路径，**属用户私有数据**，按红线该在 `~/.vibe-research/`；长驻进程要有轮转上限；`Start-Process -RedirectStandardOutput` 会吃掉控制台输出，两边都要得用 `Tee-Object`（PS 5.1 下与 uvicorn 行缓冲的兼容性**需实测**）|
| 3 | 辩论重试几次、要不要告诉主持人 | 重试一次 vs 多次（每次最长 300s，重试会显著拉长总时长）；「告诉主持人少了谁」是**改喂给 LLM 的内容**，属行为变更 |
| 4 | 雷达要不要自动刷新 | 现在是纯手动。自动刷新会打 108 个源，需要决定触发时机与频率——**也可能根本不该自动**（保持手动但把日期标出来就够）|
