## 实测到的事实（2026-08-03）

| 源 | 域名 | 结果 |
|---|---|---|
| 主源 `astock.stock_fund_flow_120d` | `push2his.eastmoney.com` | **0 行**。整机 `RemoteDisconnected`——同域名的 K 线端点一样挂，**直连与系统代理都不通**，去掉 Referer/Origin 也不通 |
| 备胎 `tools._fund_flow_today` | `push2delay.eastmoney.com` | 1 行（**只有当天**，无历史） |
| `a-stock-data/SKILL.md:2888` 记录的备胎 | `vip.stock.finance.sina.com.cn` | **60 行完整历史** |

**坏的是 `push2his` 这一个主机**，不是代码、不是参数、不是代理模式。

⚠️ **当前备胎是通的**，所以用户那次是 `push2his` 与 `push2delay` **两条东财线路同时挂**。
本 Goal 不是修一次抖动，是修「抖动为什么会整块失掉、且失掉了看不出来」。

## 四个结构性问题

## 两个源的字段不是一回事（这条决定了修法）

```
东财：date, main_net, small_net, mid_net, large_net, super_net      ← 四档拆分
新浪：opendate, trade, netamount, r0_net, r0_ratio, turnover, ...   ← 只有净额 + 超大单
```

新浪**没有主力/大/中/小四档拆分**。VR-GOAL-014 立过规矩：新源不提供的字段
**不返回假的 0**（当时拒绝了给 `flat` 平盘家数补 0）。这里同样适用。

## 已收敛决策（拷打于 2026-08-03）

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | `_cached` 缓存空结果修多宽 | **加可选 `valid` 谓词，只给资金流传** | ⚠️ **实现阶段被推翻，见验收判定①**：`astock.fund_flow` 全挂时抛异常，异常从 `fetch()` 穿出去根本走不到写缓存那行——守卫**永远不会触发**。变红实验撤掉它，测试全绿。已按 `CLAUDE.md`「从不执行的代码就是 bug 藏身处」删除，`_cached` 保持原样 |
| 2 | 降级链顺序 | `push2his` → **新浪** → `push2delay` | `push2his` 与 `push2delay` **同属东财、同一个风控面**，实测会一起挂（用户遇到的正是这个）。第二顺位若还在东财域内，在最常见的失败模式下必然也是空的——那不叫备胎 |
| 3 | 新浪字段口径 | **单独命名**（`net_amount` / `super_net`）+ 带 `source` 与说明，**不映射成 `main_net`**、缺的档位不补 0 | 新浪的 `netamount` 是净流入额，东财的 `main_net` 是「超大单+大单」，定义不同。映射过去就是**数字还在、含义变了、而且看不出来**——而「近20日主力净流入」正是个股页上唯一显示的那个数。VR-GOAL-014 已立「不返回假的 0」 |
| 4 | 界面改多宽 | **只治资金流**，其余 10 处 `.catch(() => {})` 记 backlog | 每个卡片「取不到该显示什么」是各自的产品决定，一次改 11 处 UI 而只有一条验收项盯着 = 在没有判据的情况下改十处界面 |
| 5 | 全挂时的响应 | **HTTP 502 + 各源失败原因**，不再是 200 + 空数组 | 静默的 200 正是这次的病根 |
| 6 | 降级链放哪一层 | **`astock.py` 数据层**，并删掉 `tools._fund_flow_today` | 备胎原先是 tools 私有的，所以辩论有、个股页没有——同一份数据两条路径两种结果。下沉后三条出口（页面 / 辩论 / MCP）一次都拿到。⚠️ 「删已有代码」属需显式授权动作，拷打时已声明 |
| 7 | 新浪要不要走 `em_get` | **不走** | `em_get` 是东财专用的 ≥1s 串行限流 + 代理探测，把新浪塞进那条队列只会拖慢所有东财请求。`SKILL.md` 判定新浪「风险低、不封 IP」；VR-GOAL-016 的护栏只盯 `eastmoney.com`，不冲突 |

## 实现中发现的问题（Spec 与拷打都没预料到的）

### ① 拷打定下的决策 1 是死代码，已推翻

拷打 Q1 定的是「给 `_cached` 加可选 `valid` 谓词，只给资金流传」。实现后做变红实验，
**撤掉守卫测试全绿**——因为 `astock.fund_flow` 全挂时是**抛异常**的，
异常从 `fetch()` 里穿出去，根本走不到写缓存那一行。守卫防的情况在本设计下不存在。

按 `CLAUDE.md`「从不执行的代码就是 bug 藏身处」删除，`_cached` 保持原样。
这与 VR-GOAL-017 里援引同一条理由拒绝竞态守卫是一致的——只是这次轮到我自己。

**决策 1 的另一半动机（消掉「`market.py` 与 `app.py` 两个同名 `_cached` 行为不同」这个坑）
未达成**，改为在 `_cached` 的 docstring 里写明为什么这里没有守卫。

### ② 一条假绿测试：打桩打错了层

`test_新浪不冒充主力净额` 第一版用的是公共的 `_chain()` helper，而它把
`_fund_flow_sina` **整个函数替换掉**了。于是这条断言检查的是「我自己写的桩的输出」，
**真正的字段映射代码一次都没跑到**——变红实验里把 `netamount` 映射成 `main_net`
再给三档补 0，**12 条测试依然全绿**。

改成在 `urllib.request.urlopen` 这一层打桩，让真实解析参与。

### ③ 新浪是倒序返回的，下游全按正序假设写

`asc=0` 表示**最新在前**，而东财 klines 是**最老在前**。下游一律按正序取窗口
（`rows[-days:]`、前端 `slice(-20)`），不归一化的话走新浪时「近 5 日」拿回的是
**三个月前那几天**——而且数字看着完全正常，界面上根本看不出来。

在源适配器里 `rows.reverse()` 归一化，补了 `test_新浪的顺序要跟东财对齐`。
**这条是真跑一次实链路、盯着返回的日期看出来的，测试没报。**

### ④ 截图第一版拍不到要证明的东西

`shot()` 用的是 `fullPage: true`，但本项目**它等于视口截图**：`Layout.tsx:51` 是
`flex h-screen`、`:169` 是 `<main className="flex-1 overflow-auto">`，
滚动发生在内部容器里、document body 从不滚动。资金面卡片在折叠线以下，
两张图**字节数完全相同**（都是同一张页首图），而断言照样绿
——`toBeVisible()` 判的是 DOM 可见性，不要求在视口内。

加了 `shotAt()`，截图前先 `scrollIntoViewIfNeeded()`。
⚠️ **这是全仓库共性**：以前各 Goal 的主体恰好在页首，才没暴露。

### ⑤ note 里混了 markdown

降级说明同时喂给 AI 和显示给用户，第一版写成 `**净额口径**`，界面上原样渲染出星号。
已去掉——这串是用户可见文案，不放 markdown。
