## 背景

自选股页现在只有行情七列（名称 / 代码 / 现价 / 涨跌% / PE / PB / 换手%）。用户要判断
「今天该点开哪几只细看」时，这一屏什么都不说——财报是不是刚出、有没有机构在跟、
机构给的价位在哪，全都要逐只切到个股数据页去翻。自选二十只就是二十次来回。

三样东西其实都已经在项目里躺着，只是没有汇到这一页：财报数据、研报列表（个股数据页
已能查）、机构评级与目标价。

顺带暴露出一个更基础的问题：`Layout.tsx:170` 的 `mx-auto max-w-6xl` 把**全部 12 个页面**
锁死在 1152px，与显示器多大无关。负责人日常用 27 寸屏，右侧一千多像素长期闲置——
所以「加几列就要横向滚动」并不是列太多，是容器把空间吃掉了。

## 垂直切片

- **角色**：使用看板的投研用户
- **动作**：打开自选股页
- **可见结果**：同一屏里除行情外，还能看到每只股票最新一期财报的发布日与关键同比、
  近半年研报的篇数 / 覆盖机构 / 评级分布 / 目标价区间，且这些列可点表头排序

|---|---|---|---|

| 2 | 研报聚合列出现且有真实值 | 出现「篇 / 覆盖 / 买入 / 增持 / 中性 / 目标价 / 最新研报日」七列；有研报的行显示实际值 | 截图 `02_研报聚合列.jpg` |

| 4 | `0` 与「取不到」可区分 | 打桩：某只近半年 0 篇研报 → 篇数显示 `0`；另一只接口未返回该 code → 全部研报列显示 `—`。两者在同一张截图里同时存在 | E2E 断言 + 截图 `03_零与缺失.jpg` |

| 11 | 合规口径已随产品更新 | `CLAUDE.md` 的红线一节写明目标价的转述口径（标注给价机构数与日期、超 90 天弱化、VR 不自行推算目标价与隐含空间） | 文件片段 |

| 13 | AI 工具与页面口径一致（决策 8） | `tools.py` 的 `query_reports` 返回的每条研报含目标价字段；`chat.TOOLS is tools.TOOLS` 仍成立、工具总数不变 | pytest 用例输出 |
| 14 | 运行时提示词不再自我抵消（决策 13） | `chat.SYSTEM_PROMPT` 同时包含「不自行推算目标价 / 涨跌空间」与「转述机构目标价须标明机构与日期」两层意思；且有一条静态护栏在这两句被删时变红 | pytest 用例输出 + 变红实验记录 |

> 第 14 条**刻意不断言模型的实际输出**——模型输出不可断言，那种验收项写了也判不了真假。
> 能验的只有「提示词里确实有这两层意思、且被删会有人知道」。决策 13 的实际效果由负责人主观感受，不进验收项。

> **判据自检已逐条做过**：
> - **时序污染**：无一条依赖「合并后 / 发布后」。第 12 条的 Actions run 在 push 到
>   `goal/**` 时即产生，写报告时已存在。
> - **度量污染**：没有用行数 / 覆盖率这类会被本 Goal 从别的方向搅动的聚合量。
>   第 7 条的 `1600` / `1152` 是固定阈值，且**必须钉死 viewport**——否则窗口一窄，
>   容器自然变窄，这条会红得毫无意义。

## 已收敛决策

> 前七条来自设计文档（brainstorming 产物）；8–13 是拷打（第一道闸，2026-08-07）的产物。
> 两者方向相反、不能互相顶替：brainstorming 往上搭方案，grilling 往下拆方案。

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 这一页要回答什么问题 | 「谁最近有新变化，值得点开细看」——时间信号优先 | 与 VR-GOAL-022「默认不替用户决定今天该关注谁」同向 |
| 2 | 「综合判断」怎么落地 | **VR 不下判断**，只把评级与财报如实聚合成客观数据；判断交给用户自己的 AI | 需要权衡的判断写死成公式必然失真；这正是本项目「只配数据、不给结论 + 三条 AI 出口」的产品前提 |
| 3 | 排版 | 一屏摊开、不折叠；**只放宽自选股一页**的容器 | 全局放宽会让 markdown 长文行宽拉到 2000px；且那是覆盖 12 页、没有编译器兜底的视觉变更，等同再来一次 VR-GOAL-021 的规模 |
| 4 | 评级呈现 | 照实给计数 + 表头常驻说明 | 实测 122 篇中减持 0、卖出 0；分布主要反映覆盖热度而非看好程度 |
| 5 | 目标价 | **要**。按机构去重给区间 + 给价机构数 + 最新日期；不给平均值、不给隐含空间% | 实测宁德 9 篇带目标价只来自 3 家；茅台的群益证券把 1525 自行下修到 1430，按篇统计会留下它已作废的值 |
| 6 | 新增列可否排序 | 除目标价外全部可排 | 沿用 VR-GOAL-022「数字能排、文字不排」；目标价是区间、无单一可比值，例外只有一条且一句话讲得清 |
| 7 | 东财挂了怎么办 | **不建降级链**，把失败做成看得见的；巨潮备用路径已实测验证并存档，不写代码 | 研报侧无等价备选，链只能建一半；且「从不执行的代码就是 bug 藏身处」 |
| 8 | 目标价要不要也给 AI | **给**，补进 `tools.py` 的 `query_reports` | 现状是分裂的：页面 `aiContext` 会给、function-calling 工具刻意不给。同一个 AI 在自选股页说得出目标价、一旦调 `query_reports` 深挖某只反而看不到，会表现得像忘了自己刚说过的话——两条路径各自都"正常工作"，这种不一致极难查。**代价**：`tools.py` 是四出口唯一真相源，MCP 也会带上目标价，而 MCP 没有 `SYSTEM_PROMPT` 约束 |
| 9 | 1800px 的富余给谁 | **容器 `max-w-[1800px]` + 表格 `w-full`** | `w-full` 会把富余**平摊给 20 列**而非在右侧留白；铺满时每列凭空胖 30px，同一行横跨整屏，与「一眼看完」相悖。表格 `w-auto` 则会随股票名字长短跳动 |
| 10 | 悬停时冻结重排 | **不做** | 本 Goal 确实放大了 VR-GOAL-022 剔出的那个风险（表格从 1100px 增至 1600px、「移除」在最右、开着实时行情每 3 秒重排）。但负责人裁定**删除是极低频动作、几乎不用**，故风险不成立 |
| 11 | 财务同比要不要上涨跌色 | **不上色**，靠 `−` 号识别 | 红绿在 A 股是**价格方向**的约定编码，用户读「绿」是"跌了"；财务同比没有这套约定，上色会被读成红=好绿=差，那是 VR 替财报下评价，撞「不做主观评分」。负数标 `--warning` 同理——把「净利下滑」标成警告色就是判断。**代价**：净利转负这个信号只靠一个 `−` 号，扫视时不跳眼 |
| 12 | 20 列怎么给出结构 | **两行表头**，第一行 `colspan` 打组（行情 / 最新财报 / 近半年研报） | 决策 11 之后已无颜色编码，唯一剩下的结构是空间。「篇 / 覆盖 / 买入 / 增持 / 中性」单看认不出归属，必须靠组标签；竖分隔线只说"这里分组了"、不说"这组是什么" |
| 13 | `SYSTEM_PROMPT` 与决策 8 冲突 | **改**：拆开「不自行推算」与「不得转述」 | `chat.py:44` 写着「不做任何买卖/评级/目标价建议」、`:66`「不预测涨跌与价位」。工具把目标价递过去、提示词又把模型的嘴堵上，决策 8 会被自己抵消，且变成**测不出来的功能**（模型输出不可断言）。新口径：*不自行推算目标价或涨跌空间；转述机构目标价时必须标明机构、日期与给价机构数* |

### 拷打查证到的两个事实

- **两行表头不会打红 VR-GOAL-022 的 E2E**：它的 `th()` 用锚定全串的正则（`^涨跌%$`），分组行的「最新财报」不会被误匹配；`rowCodes` 取 `td:nth-child(2)`，代码列位置不变。
- **但 022 的 E2E 会因别的原因必红**：它的 `setup()` 只打桩了 `/api/quote`，本 Goal 之后页面还会请求 `/api/earnings` 与 `/api/report-summary`——那两个会真打网络，既慢又可能触发 console error，而该用例末尾就有 `console_.check()`。**必须补打桩**（属「改动他人写过的已有文件」，见 Plan 授权一节）。
- **`query_reports` 的字段裁剪与 `SYSTEM_PROMPT` 的合规条款目前没有任何测试盯着**（`grep` 零命中）。改它们不会打红任何东西，但那几条红线是裸奔的。Plan 里补一条静态护栏钉住新口径。

## 不在范围内

- **隐含空间%**（目标价 ÷ 现价 − 1）。那个数不属于任何机构，且开着实时行情会每 3 秒变一次。
- **巨潮降级链**。备用路径已在设计文档里实测存档，本 Goal 不写代码。
- **全局容器分道**（表格类页宽 / 正文类页窄）。正确的长期形状，但应是独立的完整档 Goal。
- **评级变动**（`lastEmRatingName` 可推出上调 / 下调）与**一致预期 EPS / 前向 PE**
  （研报接口带 `predictThisYearEps` 等）。接口现成，本轮未要求。
- **持仓页**。同样是宽表，但本轮只动自选股页。

## 合规检查

- [x] 不涉及荐股 / 买卖时机 / 主观评分排名——VR 不产出任何判断，只转述机构原话与财报原值
- [x] ⚠️ **「不预测涨跌」这条口径本 Goal 已变**：机构目标价属价格预测。
      负责人已明确拍板要做，故须**同步修改两处**，写明新口径：
      机构目标价按原样转述、标注给价机构数与日期、超 90 天弱化显示；
      **VR 不自行推算目标价、不计算隐含涨跌空间**。
      1. `CLAUDE.md` 的红线一节——给人看的文档；
      2. `chat.SYSTEM_PROMPT`（决策 13）——**运行时真正生效的那份，更要紧**。
      产品放了目标价而文档与提示词还写着禁止，就是本项目最忌讳的「真相漂移」。
- [x] ⚠️ **目标价会经 `tools.py` 流向 MCP 出口**（决策 8 的已知代价）。
      MCP 没有 `SYSTEM_PROMPT` 约束，提示词由对接的宿主提供，VR 管不到。
      负责人已知情裁决。
- [x] 不把打板原始池（含个股名单）直接暴露到 API 或 UI——本 Goal 不碰打板层
- [x] 新增的用户数据只落本地——本 Goal 不新增任何用户数据，排序偏好沿用已有的 localStorage
