# VR-GOAL-024 ｜ 自选股页增加「下次财报发布日期预告」

- **状态**：验收项已确认（2026-08-08）→ 待 Plan 确认
- **档位**：完整闭环
- **创建日期**：2026-08-08
- **slug**：`next-earnings-date`
- **分支**：`goal/VR-GOAL-024_next-earnings-date`

## 背景

VR-GOAL-023 把「最新一期财报什么时候发的」放上了自选股页。但那是**回头看**——
它回答不了「这周谁要出财报」。而对使用这一页的方式来说，后者往往更要紧：
财报发布前后是信息量最集中的时点，知道茅台还有 7 天出半年报，和知道它 4 月出过一季报，
是两件不同的事。

A 股有强制的**预约披露制度**：上市公司必须提前公告定期报告的预计披露日期，改期也要公告。
这份数据是公开、客观、可核对的，正好符合本项目「只配数据」的定位。

数据源已实测（见「数据源实测」一节），成本可忽略，且**不引入任何新依赖**——
它和 VR-GOAL-023 的业绩报表是同一个东财 datacenter，可以复用已经铺好的批量端点模式。

## 垂直切片

- **角色**：使用看板的投研用户
- **动作**：打开自选股页
- **可见结果**：每只股票多显示一格「下次财报」——预约披露日与还有几天，
  查不到下次的（刚披露完、下期预约日尚未公布）明确显示为查不到，而不是空白

## 数据源实测（2026-08-08）

东财 `datacenter-web`，`reportName=RPT_PUBLIC_BS_APPOIN`：

| 事实 | 实测值 |
|---|---|
| 批量 | **一次请求查多只**，8 只 **0.19s** |
| 依赖 | 无，走 `astock.em_get`（与 `batch_earnings` 同款） |
| 关键字段 | `APPOINT_PUBLISH_DATE`（预约披露日）、`IS_PUBLISH`（是否已披露）、`RESIDUAL_DAYS`（**上游已算好的剩余天数**）、`REPORT_TYPE_NAME`（如「2026年 半年报」） |
| 改期记录 | `FIRST_APPOINT_DATE` + `FIRST_/SECOND_/THIRD_CHANGE_DATE`，改过几次都在 |

实测样本（`filter` 取 `IS_PUBLISH="0"`、按预约日升序，每只取最早一条）：

```
600519 贵州茅台  2026年 半年报  预约 2026-08-15  剩余 7
601318 中国平安  2026年 半年报  预约 2026-08-21  剩余 13
300059 东方财富  2026年 半年报  预约 2026-08-22  剩余 14
002463 沪电股份  2026年 半年报  预约 2026-08-26  剩余 18
688017 绿的谐波  2026年 半年报  预约 2026-08-27  剩余 19
000858 五粮液    2026年 半年报  预约 2026-08-29  剩余 21
600036 招商银行  2026年 半年报  预约 2026-08-29  剩余 21
→ 8 只只回 7 只
```

⚠️ **300750 宁德时代查不到**：它半年报已于 07-25 披露，而三季报的预约日尚未公布。
这不是 bug，是披露制度决定的——**「下次财报」在刚披露完的那段时间必然是空的**，
而那恰恰是这只股票财报数据最新鲜的时候。这一格显示什么必须在拷打里拍板。

## 验收项

| # | 验收项 | 判据 | 证据形态 |
|---|---|---|---|
| 1 | 「下次财报」成组出现且有真实值 | 自选股页在「最新财报」组右边出现 `下次财报` 分组与其下的列；有预约日的行显示 `08-15 · 7天` 形态 | 截图 `01_下次财报列.jpg` |
| 2 | 「待公布」与「取不到」可区分 | 打桩：某只本期已披露、下期预约日未公布 → 显示「待公布」；另一只接口未返回该 code → 显示 `—`。两者同屏 | E2E 断言 + 截图 `02_待公布与取不到.jpg` |
| 3 | 剩余天数是纯函数算的，不随时区漂移 | `days_until(预约日, 今天)` 对给定「今天」返回确定值；今天 / 明天 / 昨天 / 跨月 / 跨年各有用例；**不采用上游 `RESIDUAL_DAYS`**（逾期时它是 `null`） | pytest 用例输出 |
| 4 | 已过预约日仍未披露：中性表述且不上色 | 打桩预约日为 101 天前且 `IS_PUBLISH=0` → 显示「已过 101 天」（不是负数、不用「逾期」字样），且其 computed color **不等于**任何一档高亮色 | E2E 断言 + 截图 `03_已过预约日.jpg` |
| 5 | 三档高亮在两个主题下都达 AA | 6 个新 token（3 档 × 2 主题）对各自卡片底色**均 ≥4.5:1**，且同主题内相邻档的对比度差 ≥1.5（拉得开） | pytest 输出（含实测数值表） |
| 6 | 高亮只在 ≤5 天内出现，且越近越深 | 打桩 6 / 5 / 3 / 1 天四种：6 天不上色；5 天、3 天、1 天分属三档且 computed color 两两不同 | E2E computed style 断言 + 截图 `04_三档高亮.jpg` |
| 7 | 端点契约 | `GET /api/next-earnings?codes=`：合法 codes 返回 `{code: {...}}`；非 6 位数字 → 400；超过 100 个 → 400；取不到的 code 不出现在返回里 | pytest 用例输出 |
| 8 | 数据源挂掉不拖垮页面 | 打桩该端点 502 → 其余 20 列照常、顶部提示条说明哪一块不可用、console 无 error | E2E 断言 + 截图 `05_预约源挂掉.jpg` |
| 9 | AI 能拿到 | 「让 AI 读自选」的 context 含下次财报预约日与剩余天数 | E2E 断言 context 文本 |
| 10 | 顺带修掉 023 的空头承诺 | 目标价表头那个 `Info` 图标**悬停能出提示**，且 `aria-label` 含真正的解释文本而非「目标价说明」四个字 | E2E 断言 `title` 属性 |
| 11 | 全套验证通过 | `./ci.ps1` 全绿（无豁免）；本分支 Actions 最近一次 run 为绿 | 命令输出 + Actions run URL |

> **判据自检**：
> - **时序污染**：无一条依赖「合并后 / 发布后」。第 8 条的 Actions run 在 push 到 `goal/**` 时即产生。
> - **度量污染**：未使用行数 / 覆盖率这类聚合量。
> - ⚠️ **第 3 条特意不断言"剩余天数等于某个具体数字"**——那个数每天都变，写死明天必红。
>   断言的是**纯函数对给定「今天」的确定输出**，时间由参数注入。

## 已收敛决策

> 拷打（第一道闸）的产物。**需求明确、做法单一（复用 VR-GOAL-023 的批量端点模式），
> 只剩取舍要拍板，因此直接 grilling，不走 brainstorming。**

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 这一列一年有 5 个月对全市场是空的（实测预约表在报告期末前后才入库），怎么办 | **常驻一列，空时显示「待公布」，表头挂说明** | 列的出现/消失会让人以为坏了（022 特意给未排序列也占箭头位子就为防抖动），且隐藏＝用户永远不知道有这功能。「待公布」**本身是信息**——这一期还没排上交易所的表，和「取不到」是两回事 |
| 2 | 临近财报要不要高亮 | **要**，5 天起 | 负责人裁定，覆盖了我的推荐（我原本认为高亮是 VR 替用户标「这只值得现在看」，与 022 决策 3 的那条线接近） |
| 3 | 改期记录（`FIRST_/SECOND_/THIRD_CHANGE_DATE`）要不要显示 | **不显示** | 实测只有 4.2% 改过期；且孤零零一个「改期」记号会被读成"推迟、公司有事"，而**实测多数改期是提前**（样例 5 家 4 家提前）——那个记号的信息量是负的；另外字段语义未查清（容百科技首次 08-01 → 改为 08-25 → 最终却是 07-23，三个数对不上） |
| 4 | 这一列摆哪 | **单独成组「下次财报」，放「最新财报」右边，组内 1 列** | 不并进「最新财报」组：那组五列全在描述**同一期**报告，塞进一个描述**另一期**的列，读者会问「营收同比是上次的还是下次的」。不拆成「预约日 / 剩余」两列：两者是同一个值的两种写法，排序结果完全相同，等于两个位置表达一个事实 |
| 5 | 高亮阈值 | **5 天**，具名常量 | 实测 **68.8% 的公司挤在 8 月最后一周**，峰值周会大面积亮。但那几天它们确实全都临近，**高亮没说谎**；为了让标记好看而压低阈值会漏掉后天出财报的，本末倒置。先跑一个财报季凭实感调 |
| 6 | 渐变几档 | **3 档**（5-4天 / 3-2天 / 今明），**两套色阶方向相反**，载体是**文字色** | 实测无任何单一明度能同时满足两主题（暗色需 L≥48%、亮色需 L≤45%，不重叠），所以必须两套、且亮色「越紧迫越深」而暗色「越紧迫越亮」。6 档在 14px 等宽字上分不出来（亮色可用区间 L 15%~45%，切 6 档每档才差 5%）。**颜色是冗余强化**——格子里本来就写着天数，色觉障碍用户读数字不受影响，不该让颜色承重。载体用文字色不用背景块：背景块会和玻璃卡的半透明叠加打架，且非文本 3:1 / 文字 4.5:1 两套标准混在一格更难守 |
| 7 | 已过预约日仍未披露的要不要上色 | **不上色**，中性显示「已过 N 天」 | 这是全套里**唯一一处颜色会带褒贬**的地方：「还有 2 天」是时间事实，「已过 101 天」上色就成了"这家不对劲"的评价，撞「不做主观评分」。而且它天然不需要颜色——一个三位数天数混在一列两位数里，自己就跳出来 |

### 我自行裁定的（未占用负责人的题）

| 议题 | 裁决 | 理由 |
|---|---|---|
| 剩余天数用上游 `RESIDUAL_DAYS` 还是自己算 | **自己算** | 上游值今天是准的，但那是东财查询时算的**未文档化行为**（行的 `EITIME` 是一个多月前，字段却对得上今天）；且**逾期时上游给 `null`**，那一格会空。自己算是纯函数、可穷举、跨日边界能断言。`-m live` 里拿上游值交叉核对 |
| 取哪一条作为「下次」 | **未披露中预约日最早的一条，含已过期** | `*ST萃华` 的一季报预约 04-29 至今未披露——按此规则它自然浮出来，显示「已过 101 天」，比显示它的半年报更值得知道，且**不需要特例代码** |
| 可否排序 | **可排**，沿用 022「数字能排」 | 日期与剩余天数是**同一个值**的两种写法，按哪个排结果都一样，不破 023 立的「可排序列＝单值」 |
| 措辞 | 「待公布」/「已过 N 天」 | 「逾期」听着像指控，而这是个客观天数 |
| 高亮用哪个色系 | **`primary`（暖橙）不用 `warning`（琥珀）** | warning 自带「值得警惕」的价值判断；红绿更不行，那是价格方向的专用编码（023 决策 11） |

### 拷打查证到的事实

- **预约披露表在报告期末前后才入库**（实测五期的 `EITIME`：2025-06-26 / 2025-09-30 / 2025-12-31 / 2026-03-26 / 2026-06-30），推下来这一列**每年约 5 个月对全市场是空的**。
- **预约日高度集中**：2026 半年报 5543 家中，08-25~08-31 占 **68.8%**（3813 家），07-16~07-31 只有 1.3%。
- **逾期未披露真实存在但极罕见**：全市场 1 家（`*ST萃华`，一季报预约 04-29，已过 101 天），且上游 `RESIDUAL_DAYS` 给 `null` 不给负数。
- ⚠️ **022 与 023 的 E2E 都会被本 Goal 打红**：两份 `setup()` 只打桩了 `/api/quote`、`/api/earnings`、`/api/report-summary`，而 glob `**/api/earnings**` **匹配不到 `/api/next-earnings`**（后者不含 `/api/earnings` 子串）。两个文件都要补打桩。
- **023 的目标价表头图标是个空头承诺**：只有 `aria-label="目标价说明"`、没有 `title`——悬停无提示，读屏念出来也不含任何解释。本 Goal 顺带修掉。

## 不在范围内

- **个股数据页**。本轮只动自选股页。
- **提醒 / 推送**。不做「财报前 N 天通知」这类主动行为。
- **改期记录**（决策 3）。
- **业绩预告 / 业绩快报**。**已实测确认它和本 Goal 是两种东西**：预约披露是「未来的一个日期、有强制日程」，业绩预告是「已发生的一次披露、带数字、没有日程」——**不存在"下次业绩预告什么时候发"可追踪**。它值得做，但自己就有三处要拍板（一家公司多行：天能股份本期营收/扣非净利/归母净利各一条；幅度不带符号、须结合 `PREDICT_TYPE` 才不读反——天能扣非那条「预减 657%~749%」是下降不是增长；`PREDICT_FINANCE` 取值是「归属于上市公司股东的净利润」这类全称）。已记 backlog，独立完整档。
