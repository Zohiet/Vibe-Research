# VR-GOAL-024 ｜ 自选股页增加「下次财报发布日期预告」

- **状态**：草稿（等第一道闸）
- **档位**：完整闭环
- **创建日期**：2026-08-08
- **slug**：`next-earnings-date`
- **分支**：`goal/VR-GOAL-024_next-earnings-date`

## 背景

VR-GOAL-023 把「最新一期财报什么时候发的」放上了自选股页。但那是**回头看**——
它回答不了「这周谁要出财报」。而对使用这一页的方式来说，后者往往更要紧：
财报发布前后是信息量最集中的时点，知道茅台还有 7 天出半年报，和知道它 4 月出过一季报，
是两件不同的事。

A 股有强制的**预约披露制度**：上市公司必须提前公告定期报告的预计披露日期，改期也要公告。
这份数据是公开、客观、可核对的，正好符合本项目「只配数据」的定位。

数据源已实测（见「数据源实测」一节），成本可忽略，且**不引入任何新依赖**——
它和 VR-GOAL-023 的业绩报表是同一个东财 datacenter，可以复用已经铺好的批量端点模式。

## 垂直切片

- **角色**：使用看板的投研用户
- **动作**：打开自选股页
- **可见结果**：每只股票多显示一格「下次财报」——预约披露日与还有几天，
  查不到下次的（刚披露完、下期预约日尚未公布）明确显示为查不到，而不是空白

## 数据源实测（2026-08-08）

东财 `datacenter-web`，`reportName=RPT_PUBLIC_BS_APPOIN`：

| 事实 | 实测值 |
|---|---|
| 批量 | **一次请求查多只**，8 只 **0.19s** |
| 依赖 | 无，走 `astock.em_get`（与 `batch_earnings` 同款） |
| 关键字段 | `APPOINT_PUBLISH_DATE`（预约披露日）、`IS_PUBLISH`（是否已披露）、`RESIDUAL_DAYS`（**上游已算好的剩余天数**）、`REPORT_TYPE_NAME`（如「2026年 半年报」） |
| 改期记录 | `FIRST_APPOINT_DATE` + `FIRST_/SECOND_/THIRD_CHANGE_DATE`，改过几次都在 |

实测样本（`filter` 取 `IS_PUBLISH="0"`、按预约日升序，每只取最早一条）：

```
600519 贵州茅台  2026年 半年报  预约 2026-08-15  剩余 7
601318 中国平安  2026年 半年报  预约 2026-08-21  剩余 13
300059 东方财富  2026年 半年报  预约 2026-08-22  剩余 14
002463 沪电股份  2026年 半年报  预约 2026-08-26  剩余 18
688017 绿的谐波  2026年 半年报  预约 2026-08-27  剩余 19
000858 五粮液    2026年 半年报  预约 2026-08-29  剩余 21
600036 招商银行  2026年 半年报  预约 2026-08-29  剩余 21
→ 8 只只回 7 只
```

⚠️ **300750 宁德时代查不到**：它半年报已于 07-25 披露，而三季报的预约日尚未公布。
这不是 bug，是披露制度决定的——**「下次财报」在刚披露完的那段时间必然是空的**，
而那恰恰是这只股票财报数据最新鲜的时候。这一格显示什么必须在拷打里拍板。

## 验收项

| # | 验收项 | 判据 | 证据形态 |
|---|---|---|---|
| 1 | 「下次财报」出现且有真实值 | 自选股页出现该列；有预约披露日的行显示日期与剩余天数 | 截图 `01_下次财报列.jpg` |
| 2 | 查不到下次的与「没有数据」可区分 | 打桩：某只已披露完本期、下期预约日未公布 → 该格显示明确的「待公布」态；另一只接口未返回 → 显示 `—`。两者在同一屏 | E2E 断言 + 截图 `02_待公布与取不到.jpg` |
| 3 | 剩余天数由后端按当日计算或采用上游值，且不随前端时区漂移 | 纯函数对给定「今天」与预约日的组合返回确定天数；跨日边界（今天 / 明天 / 昨天已过期）各有用例 | pytest 用例输出 |
| 4 | 已过预约日但仍未披露的情况有明确表现 | 打桩预约日为昨天且 `IS_PUBLISH=0` → 该格不显示负数天数，而是明确的「已逾期」或等价表述 | E2E 断言 + 截图 `03_逾期未披露.jpg` |
| 5 | 端点契约 | `GET /api/next-earnings?codes=`：合法 codes 返回 `{code: {...}}`；非 6 位数字 → 400；超过 100 个 → 400；取不到的 code 不出现在返回里 | pytest 用例输出 |
| 6 | 数据源挂掉不拖垮页面 | 打桩该端点 502 → 其余 20 列照常、顶部提示条说明哪一块不可用、console 无 error | E2E 断言 + 截图 `04_预约源挂掉.jpg` |
| 7 | AI 能拿到 | 「让 AI 读自选」的 context 含下次财报预约日与剩余天数 | E2E 断言 context 文本 |
| 8 | 全套验证通过 | `./ci.ps1` 全绿（无豁免）；本分支 Actions 最近一次 run 为绿 | 命令输出 + Actions run URL |

> **判据自检**：
> - **时序污染**：无一条依赖「合并后 / 发布后」。第 8 条的 Actions run 在 push 到 `goal/**` 时即产生。
> - **度量污染**：未使用行数 / 覆盖率这类聚合量。
> - ⚠️ **第 3 条特意不断言"剩余天数等于某个具体数字"**——那个数每天都变，写死明天必红。
>   断言的是**纯函数对给定「今天」的确定输出**，时间由参数注入。
