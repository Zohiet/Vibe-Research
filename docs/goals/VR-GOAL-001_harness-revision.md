## 背景

2026-07-30 落地了第一版 Harness Engineering 闭环（commit `7bcf62a`），随后做了一轮拷打，暴露出四类问题：

1. **自证闭环**：验收项由 AI 写、验收结论也由 AI 下，唯一人工闸门是 Plan。等于自己出卷、自己判分。
2. **粒度失配**：闭环触发条件按「碰了哪个区域」划，导致三行 bugfix 也要五份产物。流程重到会被绕过，比一开始就定轻更糟。
3. **回滚与发布不成立**：Goal 直接在 dev 上做，一个没过验收的 Goal 会卡住所有已通过的；Plan 模板里写的「回滚 = `git checkout main`」是错的，那只是去看旧代码。
4. **文档债扩散**：一条 Windows 专属的测试失败被当成「基线」写进五个地方，每处都要解释一遍「1 failed 是正常的」。根因只是测试里写死了 `python3`。

不改的话，这套流程会以「看起来严谨、实际自说自话」的状态固化下来，且每加一个 Goal 就多一次绕过它的理由。
