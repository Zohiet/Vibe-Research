# VR-GOAL-025 ｜ 把裸奔的合规红线逐条钉进静态护栏

- **状态**：验收项已确认（2026-08-08）→ 实现中
- **档位**：轻量
- **创建日期**：2026-08-08
- **slug**：`compliance-guardrails`
- **分支**：直接在 dev（轻量档）

> **档位说明（偏离前缀默认，按 `goal_workflow.md` 要求写明理由）**：
> 按提交前缀反推 `test:` 默认是**豁免**。判为**轻量**的两条理由——
> ① 有真取舍要拍板（钉到什么粒度、钉哪些文件、三条出口的口径是否统一），需要一道闸；
> ② **护栏一立起来就可能发现某条红线已被违反**，那时要改的是提示词或调用关系，
> 那是行为变化，超出豁免的定义。

## 背景

合规是本项目的第一条红线，而它目前主要靠**提示词里的几句话**兜着。VR-GOAL-023 建了
`test_ai_outlet_discipline.py`，但覆盖面比想象的窄。实测缺口（`grep` 逐条核过）：

| 位置 | 合规语句 | 现有覆盖 |
|---|---|---|
| `chat.SYSTEM_PROMPT` | 不推荐任何具体买卖 / 不给买卖时机 / 不承诺收益 / 不打分排名 | ✅ 已钉 |
| `chat.SYSTEM_PROMPT` | **不预测涨跌与价位** | ❌ 不在断言列表里 |
| `chat.ANALYSIS_FRAMEWORK` | 「只做客观归纳、不给买卖结论」「不给买卖建议、不自行给出评级或目标价」 | ❌ 零覆盖 |
| `debate._COMMON_RULES` | 不预测股价涨跌与具体价位 / 不给买卖时机 / **不给目标价** / 不给仓位建议 / 不承诺收益 | ❌ 零覆盖 |
| `debate` 的 referee 角色 | 「不是裁决谁对谁错，更不是给出投资建议」 | ❌ 零覆盖 |
| `reflection.REFLECT_PROMPT` | 「不要给出你自己的投资判断、买卖建议、目标价或评级」 | ❌ 零覆盖 |
| **打板原始池不得直接接进 API / UI** | `CLAUDE.md` 明列的红线 | ❌ **零静态防线** |

**最后一条最要紧。** `astock.em_zt_topic_pool` 返回含个股 code/name 的原始池，
`CLAUDE.md` 写死「仅供 `market.py` 聚合成不含个股名的情绪指标，切勿直接接成 API 或 UI」。
实测它目前确实只被 `market.py` 调用——但**唯一的防线是「大家记得」**。
`test_fixes.py:166` 那处只是拿它做 monkeypatch，不是护栏。

仓库里已有可照抄的形态：`test_em_get_discipline.py` 就是一条静态拦截
（禁止绕过 `em_get`），且带着「为什么值得单独立一条」的说明。

**为什么这件事值得一个 Goal**：这些句子被删掉不会有任何编译错误、任何测试失败。
本仓库对付这类问题的常规手段就是静态护栏——VR-GOAL-020 的 `prose-invert`、
021 的对比度与 token 纪律、023 的 AI 出口口径，都是这么钉住的。

## 垂直切片

- **角色**：维护这个仓库的人（含未来的 AI agent）
- **动作**：删掉或改写任何一条合规红线
- **可见结果**：CI 变红，并指出被动的是哪一条、它在哪个文件

> **判据自检**：
> - **时序污染**：无一条依赖「合并后 / 发布后」。
> - **度量污染**：**刻意不用「护栏条数」「覆盖率」这类聚合量**——那会诱导凑数量。
>   判据是「每一条现存的合规语句都被覆盖」，是个可枚举的集合，不是个数字。
> - ⚠️ 第 1~3 条断言的是**语句存在**，不是模型的实际输出。模型输出不可断言，
>   那种验收项写了也判不了真假（VR-GOAL-024 验收项 14 同此）。

## 已收敛决策

> 拷打（第一道闸）的产物。**需求明确、做法单一（补测试），只剩取舍要拍板，
> 因此直接 grilling，不走 brainstorming。**

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 打板红线的真实口径是什么（实测发现文档与现实已漂移） | **承认现状、把口径写准**：原始池不得绕过 `market.py`；`market.py` 可输出客观公开榜单（含个股名）但不排名 / 不评分 / 不推荐 / 不预测。同步改 `CLAUDE.md:299` 与 `DailyReview.tsx:361` 那句错注释 | 护栏只能钉真实存在的规则。钉一条与现实不符的，要么立刻红、逼着改产品；要么钉了个真的（「只许 market.py 调用」确实成立）而旁边那句假的还在，**下一个读它的人或 agent 仍会被误导**，且 CI 绿会被读成"红线都守着呢"。2026-07-05 的产品定位调整是有意为之，清单里全是客观事实、无 VR 的评价，为让一句旧措辞成立而撤功能是本末倒置 |
| 2 | 断言粒度 | **逐字锚点 + 每条带 hint 说明它在防什么** | 「改写就红」在这件事上是特性不是缺陷：红线措辞本就不该随手改，同步改一行测试＝一个"你确实在动红线"的确认动作，成本一行、价值是留痕。**快照式最差**——snapshot 一变，人的本能是 `-u` 接受而不是想为什么，等于把硬护栏换成会被条件反射按掉的闹钟；且仓库现有零个快照测试，为这件事引入新模式不划算。同义词族的灵活性多半是假的：改成族外写法照样红，却要维护一组词 |
| 3 | `debate` 的目标价口径 | **统一为 `chat` 的口径**（可转述、须标明机构与日期与给价机构数、不自行推算） | 负责人裁定，覆盖了我的推荐。我原本建议保持更严——`CLAUDE.md` 写死 debate「产物是双方在哪儿分歧、各自要什么证据才能被证伪」，引用目标价易滑向"机构都给到 656 所以空方站不住"这类**诉诸权威替代证据**。⚠️ **这个不一致是 VR-GOAL-023 造成的**：它给 `_REPORT_FIELDS` 补了 `indvAimPriceT`，而 `debate.py:49` 的底稿含 `query_reports`，于是多空双方拿到了目标价却被告知「不给目标价」——正是 023 决策 13 判为自相矛盾的同一形态，修了 chat 没注意 debate |
| 4 | 统一后那句口径写几份 | **只把目标价条款提成共享常量**（放 `chat.py`，`debate` 与 `reflection` 本就 import chat，零新增模块与依赖边），三处引用；其余红线各出口各写 | 这一条**已用事实证明会漂**（见决策 3）。三处各写一份只是把同一个赌注再下一次——护栏只能在漂之后告知，不能阻止它漂。不提取整块：三个出口的其余红线本就该不同（debate 强调"只用底稿数据"、reflection 强调"不重写结论"、chat 有五维框架），硬凑会让每份提示词读着别扭，而可读性直接影响模型遵守度 |
| 5 | 数据诚信类语句（「不要编造数字」「只能用底稿数据立论」）要不要一起钉 | **一起钉** | 严格说它们是数据诚信而非合规，会让这个护栏文件的职责从「合规」扩成「合规 + 数据诚信」。但删掉它们的后果（模型开始编数字）比删掉「不打分排名」更严重 |

### 拷打查证到的事实

- **`CLAUDE.md:299` 的打板红线与现实已漂移**：它写「仅供 `market.py` 聚合成**不含个股名**的
  情绪指标」，而 `market.py` 的 `lianban_stocks` 输出 `code` / `name`，`DailyReview.tsx:418`
  在渲染个股名。旁边 `DailyReview.tsx:361` 的注释「聚合口径零个股名」**是明确错误**。
  该改动是 2026-07-05 的有意产品调整，代码注释里有记录，只是 `CLAUDE.md` 只吸收了一半。
- **`em_zt_topic_pool` 目前确实只被 `market.py` 调用**（`grep` 全仓库），
  但唯一的防线是「大家记得」——`test_fixes.py:166` 那处只是拿它做 monkeypatch，不是护栏。
- **既有护栏的覆盖面比 backlog 描述的宽**：`test_买卖与评分类红线一条都没被顺手放松`
  已经钉了四条措辞。我在 023 写的那条 backlog（「只钉住目标价，其余裸奔」）不准确。
- **仓库里零个快照式测试**（匹配到「快照」的几个文件是持仓快照功能）。既有静态护栏
  统一形态是：扫描 → `assert not bad, f"...{_HINT}"` → 外加一条「确实扫到了东西」自检。
- **没有任何工具调用 `em_zt_topic_pool`**，所以 `_pick` 的 16 处字段裁剪不含合规风险
  （那是 `tools.py` 的 token 成本原则），本 Goal 不钉它们。

## 不在范围内

- **模型实际输出的合规性**。不可断言，见判据自检。
- **前端文案的合规审查**。本轮只管后端提示词与数据出口，外加 `DailyReview.tsx` 那句
  与本 Goal 直接相关的错注释。
- **`tools.py` 的 16 处 `_pick` 字段裁剪**。那是「裁剪后再喂」的 token 成本原则，
  不是合规红线；要钉就得把 16 个内联元组全提成模块常量，改动面远大于收益。
  唯一有合规含义的「打板原始池不得外露」由验收项 6 覆盖，且实测**没有任何工具调用它**。
