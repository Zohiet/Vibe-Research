## 背景

第一道闸目前写的是「请负责人确认验收项」——**一道被动的是非题**。负责人扫一眼说
「可以」，这道闸就等于不存在。

但本会话的实际经过恰恰相反：**VR-GOAL-001 / 002 的所有关键设计都是在拷打里定的**，
没有一条是我起草 Spec 时想到的——

| 决策 | 来源 |
|---|---|
| 两道闸的存在本身 | 拷打第 1 问 |
| 三档分层 | 拷打第 2 问 |
| `goal/*` 分支 + `--no-ff` | 拷打第 3、4 问 |
| 截图改 JPEG + 一次定稿纪律 | 拷打第 5 问 |
| GitHub Actions 独立 CI | 拷打第 6 问 |
| 修掉基线失败而非继续养着 | 拷打第 7 问 |
| E2E 沙箱隔离 | 002 拷打中查真实持仓时发现 |

**起草能想到的都是显而易见的；真正决定成败的取舍要靠被人追问才浮出来。**
既然实践里拷打才是第一道闸的有效形式，规则就该照实写。

datagov 的 `AGENT_WORKFLOW.md` §5.3 也是同款要求（Spec 起草后、Plan 之前先走一轮拷打），
本项目此前只是没落到纸上。

## 垂直切片

- **角色**：写 Goal Spec 的 AI
- **动作**：Spec 起草完必须跑一轮 `/mattpocock-skills:grilling`，把开放决策问到收敛
- **可见结果**：第一道闸产生实际决策，而不是一次点头；收敛结论留在 Spec 里可回看

> 本 Goal 是这条规则**自己写下来之前**做的，故未走拷打。以下是实施中我自行判断、
> 需要负责人复核时留意的三处：

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 拷打是替代还是叠加在「确认验收项」之上？ | **替代** | 叠加等于两道闸挤在一处；拷打过程本就会把验收项过一遍，再单独确认是冗余 |
| 2 | 轻量档要不要跑 | **要，但按开放决策数量收** | 一刀切豁免，轻量档就会变成绕过设计讨论的后门；一刀切必问，三行 bugfix 也要五个问题，这道闸很快会被厌恶 |
| 3 | 收敛结论存哪 | **Spec 的「已收敛决策」表** | 与 datagov §15 同款。不落纸的话，结论只活在对话里，换个会话就没了——这正是 VR-GOAL-002 要解决的问题 |
