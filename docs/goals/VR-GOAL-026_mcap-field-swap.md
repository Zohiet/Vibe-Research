## 背景

wiki 侧反馈：VR 沉淀**连续第二次**把流通市值当成总市值（胜宏科技实为 2753.76 亿而非
2424 亿，大族激光此前同样）。

根因已实测确认，在 `astock._parse_gtimg`：

```python
"mcap_yi": num(44),        # 腾讯的 [44] 实为流通市值
"float_mcap_yi": num(45),  # 腾讯的 [45] 实为总市值
```

**两个字段互换。** 两条独立证据：用户给的真值 2753.76 落在 `[45]`；且**总市值恒 ≥ 流通市值**，
而 2753.76 > 2424.28。

**是孤立的两字段互换，不是整条解析偏了。** 其余字段逐一审过均正确——
`[47] = 300.18` 恰为昨收 250.15 × 1.2（创业板涨停）、`[48] = 200.12` 恰为 × 0.8，
PE / PB / 换手 / 振幅 / 量比 / 涨跌额都对得上。

### 错误流向三条路径

| 路径 | 症状 |
|---|---|
| `astock.full_valuation` → `/api/valuation` → `StockData.tsx:180` | 个股页标着「**总市值**」的数一直是流通市值 |
| `StockData.tsx:188` 的 AI context（`市值 ${mcap_yi}亿`） | → AI 分析 → 存入沉淀 → 投递 wiki。**这就是本次反馈的路径** |
| `tools.py:276` `query_company_info` 的降级分支 | `total_mcap_yi` 与 `float_mcap_yi` **双双颠倒**，四条 AI 出口都拿到错值 |

### 为什么它活到现在（这条比 bug 本身更值得记）

| 股票 | `[44]` | `[45]` | 高估幅度 |
|---|---|---|---|
| 贵州茅台 | 16366.32 | 16366.32 | **0.0%** |
| 五粮液 | 2915.40 | 2915.48 | **0.0%** |
| 胜宏科技 | 2424.28 | 2753.76 | 13.6% |
| 大族激光 | 954.34 | 1027.03 | 7.6% |
| 中国平安 | 5690.34 | 9665.86 | **69.9%** |

**茅台与五粮液的两个值几乎完全相等**，而它们正是本仓库到处在用的规范测试股。

更要命的是 `test_pure.py::test_parse_gtimg`：它把 `15000` 放进合成行的 `parts[44]`，
然后断言 `q["mcap_yi"] == 15000`。**那条测试是照着实现写的，不是照着真相写的**——
它永远抓不到这个错，只会保护它。
