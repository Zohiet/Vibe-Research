## 背景

wiki 侧反馈：VR 沉淀**连续第二次**把流通市值当成总市值（胜宏科技实为 2753.76 亿而非
2424 亿，大族激光此前同样）。

根因已实测确认，在 `astock._parse_gtimg`：

```python
"mcap_yi": num(44),        # 腾讯的 [44] 实为流通市值
"float_mcap_yi": num(45),  # 腾讯的 [45] 实为总市值
```

**两个字段互换。** 两条独立证据：用户给的真值 2753.76 落在 `[45]`；且**总市值恒 ≥ 流通市值**，
而 2753.76 > 2424.28。

**是孤立的两字段互换，不是整条解析偏了。** 其余字段逐一审过均正确——
`[47] = 300.18` 恰为昨收 250.15 × 1.2（创业板涨停）、`[48] = 200.12` 恰为 × 0.8，
PE / PB / 换手 / 振幅 / 量比 / 涨跌额都对得上。

### 错误流向三条路径

| 路径 | 症状 |
|---|---|
| `astock.full_valuation` → `/api/valuation` → `StockData.tsx:180` | 个股页标着「**总市值**」的数一直是流通市值 |
| `StockData.tsx:188` 的 AI context（`市值 ${mcap_yi}亿`） | → AI 分析 → 存入沉淀 → 投递 wiki。**这就是本次反馈的路径** |
| `tools.py:276` `query_company_info` 的降级分支 | `total_mcap_yi` 与 `float_mcap_yi` **双双颠倒**，四条 AI 出口都拿到错值 |

### 为什么它活到现在（这条比 bug 本身更值得记）

| 股票 | `[44]` | `[45]` | 高估幅度 |
|---|---|---|---|
| 贵州茅台 | 16366.32 | 16366.32 | **0.0%** |
| 五粮液 | 2915.40 | 2915.48 | **0.0%** |
| 胜宏科技 | 2424.28 | 2753.76 | 13.6% |
| 大族激光 | 954.34 | 1027.03 | 7.6% |
| 中国平安 | 5690.34 | 9665.86 | **69.9%** |

**茅台与五粮液的两个值几乎完全相等**，而它们正是本仓库到处在用的规范测试股。

更要命的是 `test_pure.py::test_parse_gtimg`：它把 `15000` 放进合成行的 `parts[44]`，
然后断言 `q["mcap_yi"] == 15000`。**那条测试是照着实现写的，不是照着真相写的**——
它永远抓不到这个错，只会保护它。

## 验收项

| # | 验收项 | 判据 | 证据形态 |
|---|---|---|---|
| 1 | 字段映射改对 | `mcap_yi` 取 `num(45)`、`float_mcap_yi` 取 `num(44)` | 文件片段 |
| 2 | 对真实数据核对通过 | `-m live` 用**两值差异大的股票**（如 300476 / 601318）核对：`mcap_yi` 等于该股真实总市值，且 `mcap_yi ≥ float_mcap_yi` | pytest `-m live` 输出 |
| 3 | 离线测试能抓住互换 | 合成行给 `[44] < [45]`，断言 `mcap_yi` 取到的是**较大的那个**——旧测试两个字段给同值、抓不住互换 | pytest 输出 + 变红实验记录 |
| 4 | 不变量护栏 | 有一条断言「总市值 ≥ 流通市值」；把映射改回去时它变红 | pytest 输出 + 变红实验记录 |
| 5 | 三条路径都拿到正确值 | `full_valuation` 的 `mcap_yi`、`query_company_info` 的 `total_mcap_yi` / `float_mcap_yi`、前端「总市值」显示 | pytest 输出 + 文件片段 |
| 6 | 全套验证通过 | `./ci.ps1` 全绿（无豁免）；`dev` 最近一次 Actions run 为绿 | 命令输出 + Actions run URL |

## 已收敛决策

> 拷打（第一道闸）的产物。

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 已投出去的错数字怎么办 | **附一个负责人自己跑的排查脚本**（`backend/audit_mcap_in_notes.py`），只列出提到市值的沉淀条目，**不判对错、不改任何文件**。wiki 侧负责人已自行订正，脚本聚焦沉淀这一侧 | 沉淀是源头、wiki 是投递目标：源头不改，哪天在 wiki 侧删掉重投，错数字原样回来。**自动订正越了设计界线**——沉淀只在「存入」那一刻写、从不修改已有内容，让它能重写历史比这个 bug 危险得多；且市值每天变，脚本没有可靠的「当时该是多少」，那需要历史数据 |
| 2 | 「总市值 ≥ 流通市值」放不放进运行时 | **只在测试里断言**（离线合成 + `-m live`） | **自动纠正最危险**：它会掩盖上游变更——腾讯真调整了字段顺序你不会知道，只会看到数据"一直是对的"，直到某个边界把它悄悄翻错；而且这个 bug 能两分钟定位，正因为解析是笨的、直的。运行时记录则没有落点：行情层的定位是「仅需标准库、**永远可用**」不能抛异常，而日志没人看——一个没人看的检查等于没有。字段顺序不随请求变化，每次代码变更验一次就够 |

| 教训写哪儿 | **就地留痕在 `test_pure.py` 那条测试旁**，不进 `CLAUDE.md` | 那份文档明写「只给地图，不复述规则」；这条教训的适用面只有一处位置式解析，写在唯一会犯这个错的地方比埋进 300 行文档更可能被读到 |
| `tools.py` 的降级分支 | 值随根因自动修正，只补一句注释说明它曾经是反的 | `float_mcap_yi` 此前只有这一个消费方，修完之后它才第一次是真的流通市值 |

### 顺带改的一处（范围内）

`StockData.tsx:188` 的 AI context 原本写「市值 X 亿」，**标签本身就有歧义**——
而这正是喂进沉淀、再投进 wiki 的那段文本。改成「总市值 X 亿」。
值的错误已由根因修复，这一处改的是**标签的可辨识度**，防同类误读再发生。
