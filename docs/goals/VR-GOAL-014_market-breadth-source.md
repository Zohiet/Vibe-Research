## 背景：从一句 AI 的抱怨挖到四层

用户在每日复盘里得到的 AI 输出以一段免责声明开头：

> ⚠️ 本次会话中行情/资金/板块类数据工具未接入，我无法拉取成交额、涨跌家数、
> 北向及主力资金流、板块涨幅榜等数据。以下复盘**仅基于页面上下文提供的四大指数收盘数据**。

走完 `superpowers:systematic-debugging` 的 Phase 1，**这一句话背后是四个独立的问题**：

| | 根因 | 证据 |
|---|---|---|
| **A** | `DailyReview.tsx:90` 的 `dataSummary` **只拼四大指数**。页面上已加载的 `overview`（涨跌家数/板块）、`emotion`、`turnover`（成交额 TOP20）、`globalIdx` 全都不进 `context` | 读代码 |
| **B** | `chat.SYSTEM_PROMPT` 开头写「你可以调用工具」并列了 23 个，而**订阅接入（CLI）在协议上没有 function-calling**。模型伸手发现没有，如实报「工具未接入」 | `chat.py:52` + `chat.py:186/316` 用同一份提示词 |
| **C** | akshare 的 `stock_market_activity_legu()` 抛 `AttributeError: 'NoneType' object has no attribute 'text'`——**乐咕页面改版**，`div.current-index` 选择器失效。`market.py:44` 的 `except: return {}` 把它吞成空 dict | 直接调用复现 |
| **D** | `requests` 打不通东财 `push2/clist`（`RemoteDisconnected`），而 **`curl` 同 URL 同时刻能通** | 见下方对照表 |

**A 的严重性由订阅接入放大**：CLI 没有工具，**`context` 是唯一通道**，而页面把这个唯一通道饿着。

**本 Goal 只修 C + D**（数据源）。A、B 另开——理由见「不在范围内」。

## 实测到的事实

**① 乐咕这条路彻底断了**（结构性，不是网络抖动）：

```
akshare 1.17.24 → stock_market_activity_legu()
  → soup.find("div", {"class": "current-index"}) 返回 None → AttributeError
后果：/api/market/overview 的 sentiment = {}（curl 证实），每日复盘页那块面板是空的
```

**② 替代源在数据层验证通过**：东财行业板块的 `f104`/`f105` 就是上涨/下跌家数。

```
fs=m:90+t:2, fields=...f104,f105 → 100 个板块
Σ上涨 4904 + Σ下跌 245 = 5149 ≈ A股总数 5400
→ 这 100 个板块是**不重叠的完整划分**，加总有效
（当日上证 +0.72% / 深证 +2.21%，与 4904:245 的比例吻合）
```

**③ 但客户端拿不到**——同机、同时刻、系统代理关闭（`ProxyEnable=0`）：

| 请求 | `requests`（`em_get`）| `curl` |
|---|---|---|
| `push2/api/qt/ulist.np/get`（单只行情）| **HTTP 200** | — |
| `push2/api/qt/clist/get`（行业板块）| **ConnectionError** | **HTTP 200，496 个板块** |
| `push2ex/getTopicZTPool`（涨停池）| **HTTP 200** | — |

**同一个主机、只有 `clist` 这一条路径拒绝 `requests`**，且是 `RemoteDisconnected`（连响应都不给就关连接）——典型的 TLS/客户端指纹拦截。

**④ 附带发现的设计弱点**：`market.py:100` 的缓存判据是 `valid=lambda v: bool(v.get("sentiment") or v.get("sectors"))`——
**部分失败也算有效**，于是「sentiment 空、sectors 有」这个坏状态被缓存 5 分钟，问题被掩盖。

## 垂直切片

- **角色**：打开每日复盘页的用户 / 拿着 `context` 作答的 AI
- **动作**：看那块「市场情绪」面板；或让 AI 复盘
- **可见结果**：涨跌家数/涨停跌停**有数**；真取不到时**明说取不到**，而不是一片空白

## 已收敛决策

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 换哪个源 | **同花顺 `stock_board_industry_summary_ths`** | 90 个行业直接带「上涨家数/下跌家数」。实测 Σ上涨 4691 + Σ下跌 728 = **5419** ≈ A股总数 5545 → 不重叠的完整划分。**决定性优势是风控面**：东财 clist 挂着的那一刻它正常返回；而 `_sectors()` 本来就在打同花顺，不引入新的依赖面 |
| 2 | 范围 | **C（换源）+ A（塞 context）** | ⚠️ **这是用户在我倾向「只做 C」之后仍然选择的。** 排查中途我给用户的 Claude Code 挂上了 VR 的 MCP，AI 从此能自己调 `query_market`——A 的**能力价值**因此消失，只剩「省 3-5 次上游往返」「上游抖动时页面已取到的更可靠」两条优化价值。用户知情后仍选择做 |
| 3 | 失败怎么可见 | **接口 + 页面 + context 三处都说** | 接口 `sentiment: null` + `errors.sentiment`（**`null` 才能让调用方分辨"没这东西"与"这次没取到"**，`{}` 是合法的空、不走任何错误分支）；页面显示「暂时取不到」；**`dataSummary` 写明"本次取不到"**——最后一条最关键：**今天 AI 正是因为不知道缺了什么，才自己编出一整段关于"工具未接入"的猜测** |
| 4 | 缓存判据 | **拆开：`sentiment` 与 `sectors` 各自独立缓存** | 成功的不重抓、失败的下次重试。**刻意不用 `and` 收紧**——`sentiment` 长期失败会拖着整个 overview 每次请求都重抓，**而反复重抓正是今天把这台机器打进东财风控的行为** |

### 排查中被证伪的四个假设（留档，因为这类误判最容易再犯）

追根因时我连续下错四个结论，**每一次都是拿一次观察当规律**：

| 假设 | 怎么被证伪的 |
|---|---|
| ① 东财对 `requests` 做 TLS 指纹拦截 | 后来 curl 也全挂 —— **封的不是客户端** |
| ② `em_get` 的长驻 Session 连接池陈旧 | **重启后端后照样失败** |
| ③ 请求过大 / `Accept-Encoding` 差异 | `pz=5` 十分钟前成功、现在同样失败 |
| ④ 东财 IP 级成片封禁 | 同一时刻 `push2ex`、`indices` **正常** |

真相：**东财对大陆住宅 IP 的间歇风控**，`a-stock-data/SKILL.md:41` 早有记载
（「非代码 Bug，加重试/换网络」）。**与本 Goal 的修法无关**——换到同花顺绕开了整个风控面。

**这段的价值不在结论，在方法**：四次都是一次失败就下判断，而每次只要多测一个对照
（curl 同时刻 / 重启后 / 换参数 / 换端点）就能当场证伪。

### 与 Spec 的偏差（三处，都是收窄）

1. **`sentiment` 不再返回 `zt/dt/zt_real/dt_real/active/speculation`。** 新数据源没有这些，
   而页面「短线情绪」区**早就在用打板四池显示涨停/跌停/连板/封板率**——旧字段是重复的。
   去掉是去重，不是丢功能。**同一个数字两个来源，迟早对不上。**
2. **也不返回 `flat`（平盘家数）。** 新源不提供，**不返回假的 0**。
3. **`_sectors()` 也不再自己吞异常**（Spec 只说了 `_sentiment()`）。两块都由 `_try()` 统一捕获，
   否则"失败要可见"这条只覆盖一半。

### 连带修改的既有测试

`test_fixes.py::test_market_degrades_without_akshare` 锁的是**旧契约**
（`_sentiment()` 缺 akshare 时返回 `{}`）。契约有意改了，测试按新契约重写并**加强**：
不只验"服务不挂"，还验 `sentiment is None` 且 `errors` 里带得出原因。

### 新引入的风险

- **同花顺也会改版。** 这次换源解决的是"乐咕坏了"，不是"永远不会坏"。
  但这次至少留下了两道防线：失败**不再被吞**（会出现在 `errors` 和 AI 的 context 里）、
  失败**不再被缓存**（不会连重试机会都没有）。
- **`breadth` 的分档阈值沿用旧口径**（`up < 600` 算冰点等）。旧口径来自乐咕的全市场家数，
  新口径来自同花顺行业加总——**两者量级一致（都≈全市场），但不是同一套统计**，
  分档边界未重新校准。目前看结果合理（4691:728 →「普涨」），但值得留意。
- **前端 `buildContext` 没有单测**（本仓库无前端测试框架），靠 E2E 读面板里的 context 预览覆盖。
  这条路径依赖「未接入 AI 时面板显示 context」这个行为——**那个行为若被改掉，这两条 E2E 会静默失效**。
