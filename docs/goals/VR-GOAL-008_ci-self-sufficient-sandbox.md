# VR-GOAL-008 ｜ `ci.ps1 -E2E` 自给自足：沙箱没起就自己起，跑完关掉自己起的

- **状态**：已实现待复核（第一道闸 2026-07-30 通过）
- **档位**：轻量（改 `ci.ps1` 行为，有行为变化）
- **创建日期**：2026-07-30
- **slug**：`ci-self-sufficient-sandbox`
- **分支**：直接在 `dev` 上（轻量档不开分支）

## 背景

`ci.ps1 -E2E` 现在要求你先手动 `./dev.ps1 -Sandbox`，不然它就报错退出。这带来两个摩擦：

1. **忘了起沙箱是常态**——命令提示写得再清楚，也是"跑一次失败、看提示、起沙箱、再跑一次"。
2. **跑完的进程没人管**。VR-GOAL-002 和 006 实施期间，我起过四次沙箱，每次都得你或我
   手动去关；这次会话里就问过你两回「要不要关掉」。

但**不能无条件跑完就关**——那会杀掉你可能正开着手工点界面的实例。VR-GOAL-006 的
grilling 里已经确认过一次这个教训：`remove_holding` 那类"动了别人的东西却不留痕"的
设计正是 bug 温床。进程也一样。

## 垂直切片

- **角色**：跑验证的开发者 / AI
- **动作**：直接 `./ci.ps1 -E2E`，不必先想着起沙箱
- **可见结果**：沙箱没起就自动起、跑完自动关；已经起着的（你手动开的）原样保留

## 已收敛决策

> 第一道闸：`/mattpocock-skills:grilling`（需求明确，未走 brainstorming —— 见 VR-GOAL-007 分流规则）。

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | E2E 失败时是否关掉自己起的沙箱 | **成功才关，失败留现场** | E2E 挂了以后第一件事往往是打开 5900 用眼睛看页面，而 Playwright 的 trace 只能回放、不能交互。失败是低频事件，排查价值高于清理；成功路径（高频）保持干净就达到了目的 |
| 2 | 硬杀 ci.ps1 后的孤儿进程 | **只用 `try/finally`，孤儿靠 `-StopSandbox` 手动清** | PID 文件方案看似彻底，但 PID 会被系统回收——照旧 PID 杀会**误杀无关进程**，且静默难归因。用低频问题（硬杀）换高危问题（误杀）不划算。孤儿代价很低：两个空闲进程，下次跑还会被复用 |

**以下由撰写者判定，无需拍板（按「宁可零问题」原则未占用负责人）：**

- **前端就绪判据 = 探 `localhost:5900/api/health` 且 `sandbox:true`**。一次验两件事：
  前端在服务 + **代理指向的是沙箱后端而非 8900 的真实数据**。只探端口会被僵尸端口骗过
  （本会话实测过 5899 处于 LISTENING 但不响应的状态），只探 `GET /` 验不到代理指向。
- **启动方式**：`Start-Process -WindowStyle Hidden -PassThru -RedirectStandardOutput`。
  **不能照抄 `dev.ps1` 的 `-NoExit`**——那是给人手动调试用的可见窗口且永不自关。
  已实测：能拿到 PID、日志实时写入、`Stop-Process` 干净杀掉。
- **日志**落 `.sandbox-data/ci-backend.log` 与 `ci-frontend.log`（已被 `.gitignore` 覆盖）。
  既然决定失败时留现场，就得连日志一起留——只留一个看不到后端报错的界面等于没留。
- **超时 60 秒**轮询，超时明确报错并附日志路径，不静默卡住。
- **`-StopSandbox`** 是显式意图：关掉 8901 / 5900 上的进程，不追究是谁起的。
- **启动前做端口预检**（实施中补的，见「与 Goal Spec 的偏差」）：端口被非沙箱的东西
  占着就立刻点名，不要等 60 秒超时再让人翻日志。

### 与 Goal Spec 的偏差

**补了一道端口预检**（Spec 里没有）。第 5 条初次实测时，安全属性是成立的——E2E 确实
没跑到真实数据上——但**路径不对**：5900 被占 → `--strictPort` 让新前端起不来 → 轮询
60 秒超时 → 报「沙箱未就绪」。结果对，但用户要等 60 秒、还得翻日志才知道真正原因是
「有个前端连着你的真实后端」。

补了预检后：**15 秒内直接点名**这个最危险的错配。安全属性没变，诊断质量差别很大。

## 复核要点

**没达成 / 部分达成的验收项**
- 无。七条全部达成。

**与 Goal Spec 的偏差**
- 补了端口预检（Spec 未列）。理由见上：原实现安全但诊断差，用户要等 60 秒且看不出真因。

**新引入的风险**
- **硬杀 `ci.ps1` 会留下孤儿进程**（这是决策 #2 明确接受的取舍）。孤儿不影响正确性——
  下次跑会探测到并复用——但会一直占着 8901/5900。发现桌面上有残留就跑
  `./ci.ps1 -StopSandbox`。
- **`-StopSandbox` 不问是谁起的**，会关掉 8901/5900 上的一切。如果你手动开着沙箱调试，
  跑这条会一并关掉——这是显式意图的命令，符合预期，但值得知道。
- 自动起沙箱依赖 conda 环境 `tradingagents` 与 `npm` 可用。环境坏了会在 60 秒超时后
  报错并给出日志路径，不会静默卡住。

**如需撤销**

git revert <本次提交 sha>
