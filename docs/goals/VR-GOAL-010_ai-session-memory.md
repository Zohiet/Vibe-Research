## 背景

**现象**：所有 AI 产出（问 AI 对话、每日复盘、资讯提炼要点、多空辩论、反思审计）
切到别的页面再回来就没了。

**根因**（走完 `superpowers:systematic-debugging` 的 Phase 1，已定位，非猜测）：

- 全站只有四样东西被持久化：侧边栏折叠、主题、AI 接入配置、沉淀迁移标记
  （`grep storageSet/storageGet` 全量核对）。**AI 产出一个都不在里面。**
- 所有 AI 输出都是路由组件里的裸 `useState`：
  `AskAiButton.tsx:36` 的 `msgs`、`DailyReview.tsx:25` 的 `review`、`Debate.tsx:38` 的 `stages`。
- `router.tsx` 是标准 React Router v6，**没有任何缓存层**。切路由 = 组件卸载 =
  `useState` 连同内容一起销毁；回来时是全新组件，初始值 `""` / `[]`。

**佐证（把"卸载"和"关闭"分开）**：`AskAiButton` 的 `close()`（`:54`）只做 `setOpen(false)`、
**没有清 `msgs`**——所以同一页上关掉面板再打开，对话还在；切页再回来才没。
**触发点是卸载，不是关闭。**

原设计把「留下来」交给手动「存入沉淀」。但用户要的生命周期是另一件事：
**只是切过去看一眼行情，回来对话应该还在**，这和「要不要归档」无关。

**用户明确的生命周期**：活过浏览器刷新与关闭标签页，**死于后端进程重启**。

## 垂直切片

- **角色**：在某个页面和 AI 聊了几轮的用户
- **动作**：切到别的页面看行情再切回来；或者关掉浏览器重开
- **可见结果**：对话原样还在，并标着生成时间。**关掉后端进程再起，就干净了**

## 已收敛决策

> 第一道闸：`/mattpocock-skills:grilling`（需求明确，未走 brainstorming——VR-GOAL-007 分流规则）。
> #1–#7 出自根因分析后的初稿，**#8–#12 出自拷打**，其中 #9、#10 是初稿完全没想到的。

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 存哪儿 | **后端进程内存，不落盘** | 用户要的生命周期就是「后端进程的寿命」。存在后端内存里，**这个生命周期是事实而不是规则**——进程停了内存自然没了，没有任何判断逻辑可以出错。备选 localStorage + `boot_id` 校验多了一套"该不该清"的机制，且 localStorage **写满会直接抛异常导致整页白屏**（`CLAUDE.md` 记着的坑），而 AI 输出恰恰最容易撑爆它。`market.py:17` 已有同款模块级内存缓存先例 |
| 2 | 内存会不会爆 | **不会，但仍设上限** | 实测用户已有 9 条 AI 产出共 **20.6 KB**，最大单条 5.6 KB。推算 12 个页面各聊 10 轮 ≈ 400 KB，而后端空跑本身占一百多 MB。要存的**只是文本**——「问 AI」是无状态 HTTP，每次重发历史，没有常驻会话；`cli-*` 订阅接入也是 spawn 一次就退出 |
| 3 | 端点形态 | **一套 KV**：`GET/PUT/DELETE /api/aisession/{key}` | 5 处产出共用，不给每个功能开专用端点 |
| 4 | key 怎么定 | **各页显式传 `sessionKey`** | 不能按 `context` 哈希——context 含实时行情，**价格一跳 key 就变、对话就"丢"了**；也不能只按路由路径——`/stock-data` 看不同股票会串成一段对话 |
| 5 | 什么时候写 | **流结束写一次 + 中止时写一次**，不逐 delta 写 | 逐 token PUT 就是每秒几十个请求 |
| 6 | 多标签页 | **共享同一份** | **这不是选择，是需求推导出来的**：要「关掉网页再进去还在」，key 就不能绑标签页——绑了的话新标签页就是新 key、什么也看不到。代价见「已知风险」 |
| 7 | 落盘红线 | **绝不落盘** | AI 对话是用户最私密的内容。只有主动「存入沉淀」才写磁盘，这条界线不因"顺手"而模糊 |
| 8 | 恢复出来的内容陈旧了怎么办 | **一律恢复，但标注生成时间**（隔天显示「昨天」） | 后端可能连开数天，周一的「每日复盘」周五还写着"今日大盘"；问 AI 里三小时前的"当前 PE 32 倍"也可能不对了。**陈旧是所有 AI 产出的普遍现象，不是某功能的特例**——统一标时间，比给每个功能定制过期策略更经得起将来加功能。判断交还用户，与「只配数据、不给结论」一致 |
| 9 | 切页时正在生成 | **仍然中止，但保留已生成的部分并标「已中断」** | 初稿沿用现状（丢弃）。但**那半段 token 早就付过费了**（API 按生成计费，CLI 是已 spawn 的一次），中止只省下剩余部分，丢掉已收到的是纯亏。而 AI 习惯把结论放前面，半截答案常常有用。只改「不再丢弃」一件事，中止行为与额度策略不动 |
| 10 | 修复会堵死一个现有逃生口 | **面板里加「清空对话」** | 你现在重置跑偏的对话，用的是「切走再切回来」——一个没人设计过但确实在用的手段。改完它就没了，想重开只能杀后端（顺带清掉行情缓存和所有页面的对话，代价与目的完全不成比例）。**修 bug 时移除了某个既有行为，就得先备好替代品** |
| 11 | 上限与淘汰 | **每 key 256 KB + 最多 100 个 key，满了 LRU 丢整个 key；不做字节总账** | 初稿写「全局 8 MB 字节账」，但按实测用量**永远不会触发＝从不执行的死代码，写错了也没人发现**。改成两个整数比较：上界隐含 25 MB，且「造 101 个 key」在测试里很容易触发，不是死代码。`OrderedDict.move_to_end` / `popitem(last=False)` 几行实现 |
| 12 | 范围 | **5 处全做** | 用户原话是「所有页面和 AI 对话的功能……内容就消失了」。**修 3 处等于没修**——剩下两处照样丢，抱怨一字不变，而「修过了但还是会丢」比没修更伤信任。通用 KV 做完后，每处接入只是"读一次 + 写一次"，边际成本很低 |

**以下由撰写者判定（grilling 中已过目）：**

- **key 命名**：`daily-review` / `portfolio` / `watchlist` / `stock:600519` / `sector:ai-chain` /
  `intel:半导体` / `debate:600519` / `reflect:<noteId>`。
- **key 限制** `[A-Za-z0-9:_\-一-龥]{1,64}`，超限 400。纯内存字典，不涉及文件路径，
  不存在路径穿越问题。
- **后端拉不到就降级为空、不报错**（与 `tools.py`「失败不抛」同源）。副功能不能干掉主页面。
- **端点走既有全局鉴权**（`VR_API_KEY`），无新增鉴权面。
- **恢复时机**：页面 mount 时拉，不等到打开面板——否则打开面板会先闪一下空白。

> **E2E 怎么绕开「没有 LLM 就测不了 AI 功能」**：沙箱不会配 API key，验收脚本
> **不真的调 AI**，而是用 `page.request.put` 直接往 `/api/aisession/{key}` 塞一段预置会话，
> 再验证界面把它恢复出来。测的正是本 Goal 的机制（存 → 取 → 渲染），
> 不测 AI 本身——AI 输出质量本来也不是这个 Goal 的判据。

## 已知风险

- **多标签页同页同时聊 → 后写覆盖先写**。写入是整段覆盖、不是合并。
  发生条件苛刻（同时开两个标签页、停在同一页面、都在聊），
  **接受并记录，不引入版本号/冲突检测**——为几乎不发生的场景引入一套需要正确性论证的机制不划算。
- **流跑到一半强杀浏览器**（不是切页，是直接关进程）这一轮会丢：写入发生在流结束或中止时，
  强杀没有机会触发任何一个。
- **恢复出来的对话继续追问时，页面上下文是新拉的**（行情已变）。这是期望行为——
  AI 应该看最新数据——但历史里可能还留着旧价格。决策 #8 的时间标注就是为这个。

## 不在范围内

- 不落盘、不做跨设备同步、不做多标签页冲突合并
- 不改「存入沉淀」的任何行为
- 不改 `chat.py` / `debate.py` / `reflection.py` 的对话逻辑本身
- 不做「AI 输出质量」相关的任何事
