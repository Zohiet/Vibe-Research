## 背景

第一轮拷打时定下「两道闸 + 验收签字」，其中签字是防止闭环退化成自证的最后一环。
跑完 001 / 002 / 003 三个 Goal 后，负责人反馈：**签字这一步可以省，验收报告他自己会去看。**

签字的真实成本：每个 Goal 结尾我都停下来等一次，而实际发生的是——负责人回一句「签收」，
我再花一个来回把「签收」转录进文档。**这道闸拦不住任何东西**（他并没有在那一刻逐条复核），
却实实在在多了两个来回。

但**不能因此让我开始自己宣布「通过」**——那就把拷打第一问的结论整个推翻了。
真正要保留的是「定标准的人不能是判分的人」，要去掉的只是「阻塞等待」。

## 垂直切片

## 复核要点

**没达成 / 部分达成的验收项**
- 无。六条全部达成。

**与 Plan 的偏差**
- 轻量档无 Plan。与 Goal Spec 无偏差。

**新引入的风险**
- **这是一次防线净减少。** 原本「AI 不自证」由两件事共同保证：报告里没有结论栏 +
  负责人签字。现在只剩前者。若哪天报告的「复核要点」写得敷衍（把没达成的轻描淡写），
  **没有任何机制会拦下来**——只能靠你事后翻报告发现。
  缓解：`/vr-accept` 与模板里都写了「不要为了让这节好看而把问题往下压」，
  但那是自律，不是约束。
- 判定与合并现在解耦：你读到有问题时，代码已经在 dev 上了。撤销靠
  `git revert -m 1 <合并点>`（`--no-ff` 的用处），比签字前拦下来贵一点。

**如需撤销**

```bash
git revert -m 1 <合并提交 sha>
```

本 Goal 是轻量档、直接提在 dev 上，无合并点；要撤就 `git revert <提交 sha>`。
