## 背景

VR-GOAL-001 把闭环的**流程**修好了，但留下两个缺口：

**一、规矩散落且有重复。** 现在有四个地方在讲规矩（`CLAUDE.md`、Harness 规范正文、
`goal_workflow.md`、`VR-git` skill），其中分支模型被讲了三遍。而拷打中定下的几件事
**一个字都没落地**：提交前缀与档位的映射、合并记录该写什么、agent 哪些动作必须先问、
赶时间时的快通道。这些目前只存在于对话里——换个会话就没了。

**二、E2E 会动你的真实持仓。** 这是 VR-GOAL-001 验收时明确记录的遗留风险。
`~/.vibe-research/portfolio.json` 里是 4 个真实持仓，而 `dev.ps1` / `ci.ps1 -E2E` 都没设
`VR_DATA_DIR`——**只要哪个 Goal 的验收脚本点了持仓页的"增加/删除"，动的就是真钱记录。**
`conftest.py` 当初专门做了 pytest 侧的隔离，E2E 这条路完全漏了。

第二条是本 Goal 里唯一有实际损害风险的部分，优先级最高。

## 垂直切片

- **角色**：在本仓库工作的 AI agent 与开发者
- **动作**：把 agent 协作规则写成单一权威文档，并给 E2E 一份独立的沙箱数据目录
- **可见结果**：规矩只有一处定义、其余地方只给指针；跑验收脚本再也碰不到真实持仓

## ⚠️ 实施期间的安全要求

验收项 6 要跑一个**真的会写数据**的脚本。如果沙箱配错了，写的就是你的真实持仓。因此：

1. 实施前先备份 `~/.vibe-research/portfolio.json` 到 scratchpad，并记录 md5；
2. 第一次跑写操作脚本前，**先用只读方式确认后端确实连的是沙箱**（查 `/api/portfolio`
   返回是否为空，而非你的 4 个持仓）；
3. 跑完立刻比对 md5；不一致就立即从备份恢复并停下报告。

这三步会写进 Plan 的实施步骤。
