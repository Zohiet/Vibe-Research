# VR-GOAL-019 ｜ 辩论页：死掉的「生成中…」要能看出是死的

- **状态**：已实现待复核（2026-08-03）
- **档位**：轻量（既有行为的修正；单阶段重试按钮是新行为，已剔出，见「不在范围内」）
- **创建日期**：2026-08-03
- **slug**：`debate-dead-progress`
- **分支**：直接在 dev（轻量档）

## 背景

用户报告多空辩论页「空方研究员 · 生成中… 一直卡住了」。

**没有任何东西在跑。** 那是一份**存档**被恢复到界面上——界面把「已经死了」和「正在生成」
渲染成了同一个样子，用户连"该不该继续等"都判断不了。

## 实证（直接读后端内存里的那份存档）

```
GET /api/aisession/debate
  code=300615  rounds=1  status='底稿就绪，辩论开始'
    stage=bull   done=True    content_len=2528
    stage=bear   done=False   content_len=0      ← 空方，一个字都没有
```

后端日志（VR-GOAL-015 落的）给出时间线：

```
15:47:12  POST /api/debate      200
15:50:05  PUT  /api/aisession/debate   ← 2 分 53 秒后存档，流已结束
（此后无任何辩论请求）
```

`_CLI_TIMEOUT_S=300s` 没到，说明走的是 `catch` 分支（中止或上游报错），
而**后端对自己能看见的失败是会补 `stage_done` 的**（VR-GOAL-015 加的，
`debate.py` 里那段注释正是为此写的）——所以这次失败发生在后端视野之外。

## 三个缺陷叠出来的

| # | 缺陷 | 位置 |
|---|---|---|
| 1 | **「生成中…」只看 `!s.done`，完全不看是不是真在跑** | `Debate.tsx:237` `{!s.done && <span className="animate-pulse">生成中…</span>}` |
| 2 | **存档里的 `status` 是过期的**：写着「底稿就绪，辩论开始」而不是「已中止」/错误 | `Debate.tsx:82` 定义了 `setSta`（本地副本 + React 双写），但 `catch` 分支用的是裸 `setStatus("已中止")`——只改了 React，`finally` 存的是本地副本 |
| 3 | **失败原因根本没进存档** | `Debate.tsx:110` `session.save({code, rounds, stages, progress, missing, status})`，没有 `error` |

⚠️ 缺陷 2 尤其值得记：`Debate.tsx:76-77` 那段注释**正是在警告这个坑**
（「finally 里要存档，而那时 React 状态变量还是旧闭包值」），但它只覆盖了 `setStg`，
`setStatus` 这条漏掉了。**注释挡不住的坑，得靠类型或结构挡。**

## 范围只在辩论页

查过：`useAiSession` 另外四个消费者（`AskAiButton` / `DailyReview` / `Intel` / `Notes`）
存的都是纯文本或字典，**没有"进行中"标记**，也没有本地副本那套。不受影响。

## 已收敛决策（拷打于 2026-08-03）

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 1 | 未完成阶段怎么呈现 | **保留 + 标终态**，半截正文照常显示 | 丢弃等于制造一场**看起来完整的假辩论**——而多空辩论的产物就是「双方在哪儿分歧」，少一方不说，读的人会以为这就是全部（VR-GOAL-015 立过「缺席要让下游知道」） |
| 2 | 「注释挡不住的坑」怎么办 | **用结构挡**：`start()` 四份状态收进一个快照 + 一个 `patch()`，作用域里不再有第二个能用的 setter；另加静态护栏钉住 | 那段代码上方**逐字写着这个警告**，人照样踩了——注释这个手段在这件事上已被证伪。同 VR-GOAL-016：「写进文档」失效后改用能变红的静态检查 |
| 3 | 中止 vs 失败 | **分开记、文案分开** | 把用户自己按的停止显示成「生成失败」是**制造假故障**。这套提示的价值全靠可信——出现过一次假失败，往后所有这类提示都会被忽略 |
| 4 | `failed` 标记 | **打通到前端** | 后端 VR-GOAL-015 一直在发，`agents.ts:44` 丢掉了，于是后端能看见的失败在界面上和成功长得一样 |
| 5 | `finished` 判据 | 改成**「所有阶段到终态」**（含失败/中止） | 原来判「全都成功」，于是空方一断，多方那 2528 字连「存入沉淀」都点不了 |
| 6 | 渲染上要不要再叠一层 `running` | ⚠️ **加了又删**，见验收判定② | 两处归一化已保证 `done=false` 只在流真的在跑时存在，那条分支**永远进不去**。变红实验撤掉它 4 条测试全绿 |
