# VR-GOAL-021 ｜ 次级文字改用语义 token，不再靠透明度调弱

- **状态**：已实现待复核（2026-08-06）
- **档位**：完整闭环
- **创建日期**：2026-08-06
- **slug**：`light-theme-secondary-text`
- **分支**：`goal/VR-GOAL-021_light-theme-secondary-text`

## 背景

VR-GOAL-020 修掉了亮色下的**白字**（`prose-invert`）。用户报的「看不清」还有第二半：
**91 处用透明度把文字调弱**（`text-muted-foreground/40~80`），亮色下淡到读不动。

### 一、透明度是个天花板，不是刻度

实测（`--card` 亮色 `0 0% 100%` / 暗色 `222 40% 9%`）：

| 主题 | muted 实色 | `/80` | `/70` | `/60` | `/50` | `/40` |
|---|---|---|---|---|---|---|
| 暗色（现状） | 6.57 | 4.62 | 3.82 | **3.13** | **2.55** | **2.06** |
| 亮色（现状） | 5.65 | **3.67** | **3.01** | **2.50** | **2.10** | **1.78** |

粗体 = 低于 WCAG AA 正文的 4.5:1。而且**这是天花板问题，不是取值问题**——
把前景推到最极端（亮色纯黑 / 暗色纯白）能达到的上限是：

| 主题 | `/70` | `/60` | `/50` | `/40` |
|---|---|---|---|---|
| 暗色上限 | 9.35 | 7.13 | 5.29 | **3.82** |
| 亮色上限 | 8.52 | 5.74 | **3.98** | **2.85** |

亮色下 `/50` **就算用纯黑也只有 3.98**、`/40` 只有 **2.85**。
所以 020 里那条「调深 `--muted-foreground` 变量」的路已被证伪，**必须改调用点**。

### 二、暗色也不达标——不是亮色专属问题

暗色 `/60` 只有 3.13:1，而 `/60` 是用得最多的一档（36 处）。
用户没报暗色，但数字在这儿。暗色是本项目的默认主题、也是开发者天天看的那个，
**"没人抱怨"不等于"达标"**。

### 三、7 处合规文本正躺在最淡的那一档

这是本 Goal 最硬的理由，不是审美问题：

| 透明度 | 位置 | 文本 |
|---|---|---|
| `/50` | `pages/DailyReview.tsx:441` | 客观公开榜单，非推荐 / 非预测 / 不构成投资建议 |
| `/60` | `components/layout/Layout.tsx:160` | v0.2.2 · 不荐股 · 不预测 · 无倾向 |
| `/60` | `components/ui/EarningsSnapshot.tsx:59` | 最新财报 + 前向一致预期 + 估值位置…（含不预测措辞） |
| `/60` | `pages/Intel.tsx:377` | 只做公开信息聚合、不做推荐、不预测涨跌 |
| `/60` | `pages/StockData.tsx:352` | 只显示当前处于历史什么位置，不构成买卖建议 |
| `/60` | `pages/StockData.tsx:479` | 资金/筹码为公开客观数据…不构成任何买卖建议 |
| `/70` | `components/ui/Disclaimer.tsx:7` | 不推荐个股、不预测涨跌、不构成投资建议 |

`CLAUDE.md` 的第一条红线是合规。**把免责声明渲染成 2.10:1，等于在形式上写了、在事实上没说。**

### 四、91 处不是 91 个设计判断

按"这行字是什么"分类，只有 5 类：

| 类别 | 处数 | 透明度分布 |
|---|---|---|
| 次要文字（说明 / 时间戳 / 代码 / 空态提示） | **75** | `/80`×1 `/70`×16 `/60`×36 `/50`×19 `/40`×3 |
| 图标 / 装饰（非文字，WCAG 走 3:1 的非文本标准） | 7 | `/60`×1 `/50`×1 `/40`×5 |
| 占位符 `—` / 分隔符 `·` | 4 | `/40`×4 |
| 恒隐藏（`/0`，hover 才显的外链图标，**按设计如此**） | 2 | `/0`×2 |
| 合规文本（已计入上面的"次要文字"，单独列是因为它另有要求） | 7 | `/70`×1 `/60`×5 `/50`×1 |

**同一件事（"这行比正文次要"）被三个不同的透明度随手表达了三遍**——`/70` `/60` `/50`
之间没有可解释的语义差别，纯属历次写代码时随手取值。真正要拍板的是
「这个应用的文字分几级」，定完之后 91 处是机械归桶。

不做的话：亮色主题的小字整体不可读，暗色勉强能看但同样不达标，
且合规声明在两个主题下都处于"写了等于没写"的状态。

## 垂直切片

- **角色**：使用看板的投研用户（两个主题都算）
- **动作**：在任意页面阅读正文以外的小字——说明、时间戳、空态提示、免责声明
- **可见结果**：这些字有明确的层级且都读得动，而不是淡到需要凑近看

## 验收项

| # | 验收项 | 判据 | 证据形态 |
|---|---|---|---|
| 1 | 文字颜色不再用透明度表达层级 | 静态护栏：`src/**/*.tsx` 里**不得出现** `text-muted-foreground/NN`（`/0` 的 hover 例外需显式白名单并写明理由）。做变红实验 | pytest 输出 + 变红实验记录 |
| 2 | 每一级文字 token 在**两个主题**下都达标 | 纯计算测试：解析 `index.css` 里定义的文字 token，对各自主题的 `--card` 算对比度，**每一级 ≥ 商定阈值**（阈值由拷打决定）。两个主题各一组断言 | pytest 输出（含实测数值表） |
| 3 | 7 处合规文本达到正文级可读 | 那 7 处的 computed color 在两个主题下对比度 **≥ 4.5:1**（AA 正文），逐处断言 | E2E 断言 + 截图 |
| 4 | 真实页面上确实变了，且暗色没被改坏 | 取 3 个代表页（每日复盘 / 个股数据 / 研究记录）在两个主题下截图；同时抽样断言若干真实元素的 computed color 达标 | 截图 6 张 + E2E 断言 |
| 5 | 层级仍然可辨 | 正文 / 次要 / 更次要三级之间**两两对比度 ≥ 1.5:1**——否则"都达标了但看起来一样"，等于把层次压平 | pytest 输出（数值） |
| 6 | 全套验证通过 | `./ci.ps1 -E2E` 全绿；GitHub Actions run 绿 | 命令输出 + Actions run URL |

> **判据自检**：
> - **无时序污染**：六条都在实现完成当场可验，不依赖「合并后 / 发布后」。
> - **无度量污染**：判据是**具体 token 的对比度数值**与**具体元素的 computed color**，
>   不是"改了多少处""覆盖率"这类会被本 Goal 从别的方向搅动的聚合量。
>   —— 特意**没有**写「91 处全部改完」这种计数判据：本 Goal 同时会新增 token、
>   可能还会合并某些站点，处数会从两个方向变动，正是 VR-GOAL-002 栽过的度量污染。
> - **验收项 5 是防"过度修正"的**：只测下限会导致把所有层级都推到最深、层次消失。

## 已收敛决策

> 第一道闸（拷打，2026-08-06）的产物。

| # | 议题 | 裁决 | 理由 / 取舍 |
|---|---|---|---|
| 0 | 要不要先 brainstorming | **直接 grilling** | 做法那一层在 VR-GOAL-020 的 Q2 已由负责人拍板（"改调用点，换成够深的次级色 token"）——那正是 brainstorming 该产出的东西。本轮只剩取舍。**若拷打中发现做法未定则退回补 brainstorming**，不用"两者同等作用"糊过去（VR-GOAL-006 的教训） |
| 1 | 改哪个主题 | **两个主题都达标** | 暗色 `/60` 只有 3.13:1，同样不达标；那 7 处合规文本在暗色下也是 3.82:1。**合规是第一条红线，不该分主题豁免**。否决了「暗色像素级冻结」——那会在代码里留下一套"看起来是语义 token、实际把不达标值固化下来"的东西，比透明度更难发现 |
| 2 | 文字分几级 | **3 级：正文 / 次要 / 更次要**，后两级都 ≥4.5 | 使用规则必须能说出口，否则迟早又被随手用：**次要＝需要读的辅助信息**（说明段、免责声明、空态、错误提示）；**更次要＝不读也不影响使用的边角标记**（时间戳、序号、股票代码、"· 报告期"后缀）。规则写进 `CLAUDE.md` |
| 3 | 输入框算不算 | **算**：`bg-black/20` → 主题化的输入面 token；并**显式设置 placeholder 颜色** | `bg-black/20` 与 `prose-invert` 是同一种病——把只在暗色成立的值硬写死，本 Goal 的立意就是清掉这类东西。实测亮色下它混出 **`#CCCCCC`**：白卡上一个中灰方块。另：全仓库**从未设置过 placeholder 颜色**（`grep placeholder:` 零命中），今天它由浏览器决定 |
| 4 | 三级怎么分间距 | **次要 8:1、更次要 5:1、装饰 3:1** | 三级是零和游戏，总空间只有 4.6→17.4。实测：次要取 7:1 则两个次级只差 1.52（"分了三级看起来像两级"）；取 9:1 完全等距但正文↔次要只剩 1.93，**muted 会开始跟正文抢注意力**，而这些小字本就不该抢。8:1 把余量留在正文一侧，间距 2.18 / 1.60。更次要取 5:1 而非贴着 AA 的 4.5，留抗锯齿余量 |

## 不在范围内

- **`border-border/NN`、`bg-*/NN` 等非文字透明度**——不影响可读性。
- **`--foreground` / `--primary` / `--success` / `--danger` 等主色与语义色**不动。
- **`prose` 内部的颜色**——VR-GOAL-020 刚定，本 Goal 不重开。
- **2 处 `text-muted-foreground/0`**（`Intel.tsx:198/321` 的 hover 才显外链图标）——
  按设计如此，护栏里显式白名单并注明理由。
- **不改任何字号、间距、布局**——本 Goal 只动颜色，否则截图对比就说不清是谁的功劳。
