# VR-GOAL-016 ｜ 个股新闻 502：自己实现，走 `em_get`

- **状态**：验收项已确认（2026-08-01，拷打后）
- **档位**：轻量（三处都是既有行为的修正，不新增端点 / 页面 / 数据格式）
- **创建日期**：2026-08-01
- **slug**：`news-source-ua`

## 背景

`/api/news` 对**每一个**股票代码都返回 502。用户日志（2026-08-01）：

```
"GET /api/news?code=002290" 502    "GET /api/news?code=688820" 502
"GET /api/news?code=300446" 502    "GET /api/news?code=300476" 502
…（12 条，无一例外）
```

报错是 `新闻源异常：Expecting value: line 1 column 1 (char 0)`——JSON 解析空字符串。

**影响面**：个股数据页的「近期新闻」、多空辩论底稿的「近期新闻」一项
（辩论里会显示「未取到：近期新闻（双方立论时不得臆测这部分）」）。

## 根因（实证）

`astock.stock_news()` 把请求委托给 `ak.stock_news_em()`，而后者用的是**裸 `requests.get`**：

```python
url = "http://search-api-web.eastmoney.com/search/jsonp"
r = requests.get(url, params=params)      # ← 没有 User-Agent
data_json = json.loads(data_text.strip("jQuery3510875346244069884_1668256937995(")[:-1])
```

**东财现在对不带 UA 的请求返回「HTTP 200 + 空 body」。** 实测四组对照：

| 请求 | 结果 |
|---|---|
| HTTP，**无 UA**（akshare 现状）| HTTP 200，**0 字节** → `json.loads("")` 炸 |
| HTTP，带 UA | HTTP 200，**7347 字节**，正常 JSONP，`hitsTotal=592` |
| HTTPS，带 UA | 同上，正常 |
| HTTPS，带 UA + Referer | 同上，正常 |

**加 UA 即可**；HTTPS 与 Referer 都不是必需。

### 这个 bug 的存在本身违反了仓库硬约定

`CLAUDE.md`：

> **东财请求一律走 `astock.em_get`**……新增东财端点不要自己 `requests.get`。

`em_get` 自带三样：**UA、≥1s 串行限流（防封）、直连优先/失败降级代理**。绕过它的东财调用
**不止 `stock_news` 一处**（起草时写成「唯一」，是错的，已实测纠正）：

| 调用点 | 目标域名 | UA | 限流 | 代理降级 | 2026-08-01 实测 |
|---|---|---|---|---|---|
| `stock_news` → `ak.stock_news_em` | `search-api-web` | ✗ | ✗ | ✗ | **200 + 0 字节 → 全 502** |
| `individual_info` → `ak.stock_individual_info_em` | `push2` | ✗ | ✗ | ✗ | 裸请求 3/3 `ConnectionError`，**同一时刻 `em_get` 成功** |
| `announcements`（本仓库自己写的裸 `requests.get`）| `np-anotice` | ✓ | ✗ | ✗ | 未报错 |

两条**互相独立**的证据，说明这三处坏的方式不一样，不能一概而论：

- **`search-api` 上 UA 是分水岭**：无 UA → 0 字节，带 UA → 9918 字节，两轮复现。
- **`push2` 上 UA 不是分水岭**：带不带 UA 都 `ConnectionError`（3/3）。救回它的是
  `em_get` 的**直连/代理降级**——同一时刻 `em_get` 打同一个 URL 成功。

即：`stock_news` 缺的是 UA，`individual_info` 缺的是代理降级，`announcements` 缺的是限流。
**三处缺的东西各不相同，但根因同一个：都没走 `em_get`。**

顺带，akshare 那行 JSONP 剥壳是**硬编码的回调名**
（`strip("jQuery3510875346244069884_1668256937995(")`）——回调名一变就崩，本身是定时炸弹。

## 已收敛决策（拷打于 2026-08-01）

| # | 议题 | 结论 | 理由 |
|---|---|---|---|
| 1 | 修一处还是三处 | **三处全收口到 `em_get`** | `individual_info` 不是假设性风险，今天裸请求 3/3 失败、`em_get` 同时刻成功，它已经在坏、只是坏在没人盯的路径上。三处是同一根因的三个出口，一起修才是修根因 |
| 2 | 失败表现改不改 | **不改，保持 502**（此条从范围内删除）| 「空 vs 失败」现状已分得清（空→200+`[]`，失败→502），且下游三条路各自都已处理：AI 工具层 `exec_tool` 转 `{"error":…}`、辩论底稿层显示「未取到：近期新闻」、页面层显示错误。再在 HTTP 层做一遍就是同一份内容两处 |
| 3 | 要不要进 ≥1s 串行队列 | **进**，完整走 `em_get` | 代价是个股页 +2~3 秒（摊在已有 12~16 秒上，约 +15~20%）。跳过限流是拿「快 2 秒」换「更容易被封」，而被封的代价是整页全空——今天那 12 条 502 就是这笔账 |
| 4 | 加不加回归护栏 | **加静态测试**，并接受它给未来新代码设的门槛 | 这条约定**已经写在 `CLAUDE.md` 里了**，仍出现三处违反（其中一处是本仓库自己写的）——「写进文档」这个手段在这件事上已被证伪 |

### 不需要拍板的（查证后即唯一解，记在这里免得再问一遍）

- **JSONP 剥壳**：`cb` 是必需参数（不给 → HTTP 400），但**回调名可由我方指定**（`cb=vr` 实测生效）。
  自己指定、剥自己指定的名字即可，akshare 那个硬编码长回调名的定时炸弹自动消失。
- **字段名是对外契约，必须原样产出**：新闻四个中文键 `新闻标题 / 发布时间 / 文章来源 / 新闻链接`
  （`api.ts:154`、`StockData.tsx:430-434`、`Intel.tsx:246`、`tools.py:344`）；
  `individual_info` 九个中文键（`股票代码/股票简称/总股本/流通股/行业/总市值/流通市值/上市时间/最新`）
  直接透传给 `/api/info` 与 AI 工具。**改键名 = git 不报的语义冲突。**
- **`fields` 只请求实际用到的 9 个**（akshare 请求了 100 多个），纯瘦身，不是修复手段。
- **`_company_info` 的腾讯行情降级保留不动**：东财整体被封时它仍会执行，不是死代码。

### 为什么不写 E2E 断言

新闻能不能取到取决于当时的网络与东财风控，断言「新闻区非空」等于养一条**网络不稳就红**的测试
——正是本仓库明令反对的那类（不断言实时行情、不留会飘的失败）。
验收时手工截一张个股页新闻区的图作为证据即可。

## 与 Spec 的偏差

**范围从三处变成四处。** 新增的静态护栏刚建好就抓出第四处：`hot_concepts` 用裸
`requests.post` 打 `emappdata.eastmoney.com`，而 `em_get` 只做 GET。

处理方式是抽出 `_em_request(method, …)` 让 `em_get` / `em_post` 共享限流队列与
直连/代理探测结果，**`em_get` 的 GET 行为逐字未变**。这超出了拷打时批准的「三处」，
但正是那条决策的本意（同一根因的所有出口一起修）——已当场向负责人说明。

**顺带撤掉一条豁免**：`e2e/VR-GOAL-013_wiki-read-in-vr.spec.ts` 里为这个 bug 加过
`console_.check(["502"])`。根因既已修掉，豁免同时撤销（本仓库不留「这条不用管」的例外），
撤后该 spec 2/2 仍绿。
