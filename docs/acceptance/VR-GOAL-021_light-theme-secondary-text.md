## 二、与 Plan 的偏差

**如实列出，不为了好看抹掉。**

| # | Plan 怎么写的 | 实际 | 说明 |
|---|---|---|---|
| 1 | 「13 处 `bg-black/20` 是输入控件」 | **15 处** | 我数错了。另有 1 处 `<pre>`、1 处表格行一并改；1 处模态遮罩**保留黑色**（遮罩本就该在两个主题下都压暗背景，已白名单） |
| 2 | 护栏三条 | **四条** | 加了 `test_写死的调色板文字色必须配_dark_变体`，见下 |
| 3 | 范围只含 `muted-foreground` 系 | **多修了 2 处徽章** | `Notes.tsx` 的 `text-sky-400` / `text-violet-400`，见下 |
| 4 | 未提及 placeholder 的实现难点 | 踩了一个坑 | 见下 |

### 偏差 3：两处徽章，Plan 里没有，但不修就是漏

第三条护栏跑出来时报了 `text-sky-400` / `text-violet-400` 未注册（那是误报，
内置调色板依然有效），但**顺带暴露了真问题**：

```
Notes.tsx  多空辩论: "bg-sky-500/15 text-sky-400"
Notes.tsx  反思审计: "bg-violet-500/15 text-violet-400"
```

`sky-400` / `violet-400` 是**为深色底调的浅色**。实测亮色下
**1.84:1** 和 2.26:1——浅蓝底上的浅蓝字，基本隐形。
同一批徽章里另外三个用的是 `text-primary` / `text-warning` / `text-success`，会随主题走。

这和 `prose-invert`（VR-GOAL-020）、`bg-black/20`（本 Goal）是**同一种病**：
把只在暗色成立的颜色写死。**同一个形状第三次出现**，所以我除了修这两处，
还把它立成了第四条护栏。改法：`text-sky-700 dark:text-sky-400`（亮 5.10 / 暗 6.98）。

**这超出了已确认的 Plan 范围。** 判断依据是：本 Goal 的立意就是清掉这类硬编码，
而留着它意味着验收报告要写"亮色下还有两个标签看不清"。**如有异议，
撤掉这两行即可，不影响其余部分。**

### 偏差 4：placeholder 的坑——以及一条绿得毫无意义的测试

我先写了 `::placeholder { color: hsl(var(--subtle-foreground)) }`，测试算下来应该是 4.63:1。
**E2E 实测 2.32:1。**

原因：Tailwind preflight 里写的是 `input::placeholder, textarea::placeholder`，
比裸伪元素更具体，把我的规则整个盖掉了，实际生效的仍是它的 `gray-400`。

值得单独记一笔的是：**暗色那条测试当时是绿的**——`gray-400` 压在近黑输入框上
对比度很高。**只测暗色的话，我会以为这个机制生效了。**
这是「一个主题达标不代表机制对」的实证，也是 Q1 决定"两个主题一起做"的额外回报。

## 三、变红实验

护栏跑绿不算数。八个维度逐一注入违反：

| # | 注入的违反 | 对应的真实事故 | 结果 |
|---|---|---|---|
| 1 | 一处文字改回 `/50` | 亮色 2.10:1 | ✅ 变红 |
| 2 | 输入框改回 `bg-black/20` | 亮色白卡上的中灰方块 | ✅ 变红 |
| 3 | 亮色 muted 调回 42% | 达标线以下 | ✅ 2 条变红 |
| 4 | 两级 token 调成同值 | 层次被压平 | ✅ 变红 |
| 5 | tailwind 里删掉 `subtle` 注册 | **静默无效**：元素不报错、只继承父级色 | ✅ 2 条变红 |
| 6 | 徽章去掉 `dark:` 变体 | 亮色 1.84:1 | ✅ 变红 |
| 7 | 纪律护栏扫描目录指错 | 护栏"什么都没扫到"而假绿 | ✅ 变红 |
| 8 | 对比度测试 CSS 路径指错 | 同上 | ✅ 7 条变红 |

⚠️ **第 7 条第一次跑出来是绿的**——但那是我实验写错了：`sed` 匹配的是
`"frontend" / "src"`，而该文件里写的是 `FRONTEND / "src"`，**什么都没改**，
测试当然绿。改对之后立刻变红。
记在这里是因为它本身就是个教训：**变红实验也会"绿得毫无意义"**，
必须确认注入真的落地了（我第二次加了 `grep` 回显来确认）。

## 五、复核要点

**给负责人的三十秒版。**

1. **验收项 6 条全部达成，没有未达成项。**

2. **有 3 处超出已确认 Plan 的改动**，都在 §二 列明：两处徽章（`text-sky-400`
   `text-violet-400`）、多出来的一条护栏、`bg-black` 实际是 15 处而非 13 处。
   **前两项如有异议可单独撤掉**，不影响主体。

3. **这是一次全站视觉变更，不是局部修补。** 除了 91 处透明度，
   改 `--muted-foreground` 取值还波及 178 处不带透明度的用法，合计 **269 处 / 21 个文件**。
   **暗色（你的日常主题）的小字确实变亮了**——这是 Q1 已知情的裁决。
   若看久了觉得不合适，**不需要回滚**：改 `index.css` 里的亮度数字即可，
   对比度测试会立刻告诉你新值达不达标。

4. **新引入的依赖关系**：`text-subtle` / `text-faint` / `bg-input-surface` 三个类
   依赖 `tailwind.config.ts` 里的注册。**Tailwind 对未注册的类名不报错**——
   元素只会安静地继承父级颜色。`test_用到的自定义色类必须在_tailwind_注册`
   是唯一会为此变红的东西，**这条测试不能删**。

5. **同一个形状第三次出现了**：VR-GOAL-020 的 `prose-invert`、本 Goal 的
   `bg-black/20`、以及这两处徽章——都是「把只在暗色成立的颜色写死」，
   都只在亮色下暴露，而写代码的人默认在暗色里。第四条护栏就是为这个形状立的。

6. **`--chart-grid` / `--chart-text` / `--chart-axis` 定义了但全仓库零引用**（死变量）。
   本 Goal 刻意没动，已记 backlog。
